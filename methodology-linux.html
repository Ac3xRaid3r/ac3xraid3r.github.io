Linux privesc methodology

The exam-day flow for Linux boxes — web-first footholds, the write-to-RCE bridges, and privilege escalation ranked by frequency: password reuse, sudo/GTFOBins, SUID, cron, capabilities, and kernel last.

Exam-day flow. Synthesised from 40+ solved Linux boxes (PG Practice, HTB CPTS labs, OSCP-style). ~80% of these boxes are web-first; drill web enumeration -> known-service exploitation first.

Prime Rules

  1. Fingerprint the exact product + version, then searchsploit / Google <product> <version> exploit. The version string is the whole game on ~80% of PG Linux boxes.
  2. Try default and product-name credentials before anything hard. admin:admin, admin:password, <appname>:<appname>, root:root, guest:guest, postgres:postgres.
  3. Reuse every credential everywhere — su and ssh, every user in /etc/passwd. This alone is the privesc on ~1/3 of boxes.
  4. sudo -l -> GTFOBins is the first privesc reflex.
  5. Read source and config files for creds the moment you have any file read (LFI, disclosure, low-priv shell).
  6. Enumerate cron/timers with pspy and hunt for writable things root runs.
  7. id and getcap early — group membership (disk, docker, lxd, adm, mlocate) and capabilities are fast wins.
  8. Kernel exploits last. Enumeration beats CVE-roulette and won't crash the box.

The Distilled Methodology

Enumeration

  1. Full TCP scan -p- then -sC -sV on open ports. Note non-standard ports — Nibbles moved PG to 5437, Hunit SSH to 43022, Sorcerer to 7742. Non-defaults are almost always the intended path.
  2. Every web port: feroxbuster / gobuster with extensions, whatweb, view source, check /.git, backups, and fingerprint product + exact version.
  3. searchsploit / Google the version string. Resolves ~80% of footholds.
  4. Anonymous checks: SMB (smbclient -L, enum4linux-ng), FTP anon, Redis (redis-cli), NFS (showmount).

Foothold

  1. Prefer the known-CVE / default-cred path over brute force. Try defaults before exploits.
  2. Chain LFI/SQLi/upload into RCE using the file-write bridges (see below).
  3. Get a stable shell: upgrade TTY; use setsid / nohup if web-RCE shells die on a timer (PHP max_execution_time).

Privesc — Run in This Order

Step 1 — First 30 seconds. Run these before anything else:

id                                                                          # groups matter — see rank #6 below
sudo -l
find / -perm -4000 -type f 2>/dev/null
getcap -r / 2>/dev/null | grep -E 'cap_setuid|cap_setgid|cap_dac_override|cap_dac_read_search|cap_sys_admin|cap_sys_ptrace'

Enumerate SUID before pty.spawn — Astronaut hides /usr/bin/php7.4 from find after the upgrade.

Step 2 — Credential reuse. Try every credential for su / ssh against every user. This is the highest-ROI move.

Step 3 — Loot. Read service configs + home dirs for creds/keys; check /etc/passwd for real users.

Step 4 — Automated + cron. LinEnum-ng / linpeas plus pspy for at least 60 seconds for cron/timers and non-root-owned root services.

Step 5 — GTFOBins. For any sudo/SUID hit. Check writable scripts/units/PATH dirs root touches.

Step 6 — Kernel exploit only if all of the above fail.

Recurring "Write -> RCE" Bridges

Memorise these — every one converts a write primitive into code execution:

  • FTP/other write into Apache/nginx webroot -> drop a webshell (SpiderSociety)
  • SQL INTO OUTFILE -> webshell (Pebbles/ZoneMinder)
  • PostgreSQL COPY ... FROM PROGRAM -> direct RCE (Nibbles)
  • PHP wrappers — data://, zip://, php://filter via LFI (Snookums, Zipper)
  • Redis — MODULE LOAD .so / SLAVEOF replication / CONFIG SET SSH key drop / write cron (Wombo, Sybaris)
  • Rogue MySQL server <- client with LOAD DATA LOCAL INFILE (Mantis)
  • CMS "config field that shells out" — MantisBT dot_tool, WordPress theme editor, Monstra theme template, Gitea Git Hooks, Zabbix Scripts

Where the Credentials Come From

Because password reuse and cred-driven pivots dominate, know the standard cred sources:

  • Service config files — .env, wp-config.php, zabbix.conf.php, Grafana embedded DBs (grafana.db), Openfire openfire.script, .htusers.php (eXtplorer), Confluence confluence.cfg.xml (SpiderSociety, Zab, Workaholic, dora, Fired, BitForge)
  • Crackable hashes — bcrypt (-m 3200), MD5 (-m 0), phpass (-m 400), Atlassian {PKCS5S2} (-m 12001) -> hashcat + rockyou (Zab, Mantis, Quackerjack, Workaholic, dora, SPX, Pebbles)
  • Mailboxes / IMAP — colleagues share creds by email (Scrutiny, PostFish, HTB-Enigma)
  • Process args — /proc/self/cmdline, ps aux (clue, Mantis, BitForge — mysqldump -pFOO)
  • Git history & exposed .git — deleted files still recoverable (BitForge, Scrutiny)
  • Cron scripts & backups — hardcoded creds in root-run scripts (Mantis, BitForge)
  • Hidden files with unusual names — .~, .old, .bak, .git-credentials (Scrutiny)

Decision Tree — "I See X, Try Y"

Observation Response
See disk / docker / lxd in id output Immediate root via debugfs / docker run -v /:/mnt / lxd init container escape
See any cap_setuid* in getcap -r / Immediate root: python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'
sudo -l returns a specific binary GTFOBins first (never assume kernel exploit)
sudo -l returns a script with -C into user-writable dir Hijack Makefile / config / template
sudo -l returns any sudo path glob (/path/*.ext) Try ../ traversal from allowed prefix
sudoers Defaults includes !env_reset or env_keep+=LD_PRELOAD Env-var injection (NODE_OPTIONS, PYTHONPATH, LD_PRELOAD, PERL5OPT, RUBYOPT)
sudo -l returns systemctl status, journalctl, less, more, man Pager escape !/bin/bash
Non-standard SUID binary in /usr/bin/ strings it: watch for dlopen, dlsym, hardcoded /home/..., LD_* paths -> dlopen hijack
/etc/crontab PATH earlier than defaults + world-writable dir + unqualified binary call PATH hijack
Cron LD_LIBRARY_PATH= includes a world-writable dir Drop malicious .so with __attribute__((constructor))
Writable script in /opt, /home, or referenced by a systemd unit / cron / init.d Append SUID-bash payload
Owned SUID root binary spawned by cron / systemd — -rwxr-xr-x but you own the file Rewrite content
/var/mail/<user> exists Read every one — colleagues share creds
Two mail relay / SMTP creds Try as su password for the mail-relay user (often == root)
Any exposed .git/ git-dumper + git log --all + git show <commit>:<deleted_file>

EXAM-Day Flow (Linux)

EXAM-OK — everything here is exam-legal:

  • Nmap + NSE, feroxbuster/gobuster, hydra, netexec/crackmapexec, evil-winrm, impacket, chisel, ligolo-ng, linpeas/winpeas, GTFOBins reference, msfvenom, metasploit multi/handler, searchsploit

EXAM-RESTRICTED — one target only:

  • Metasploit auxiliary/exploit/post modules and Meterpreter -> count as your ONE. Everything CVE-shaped here has a manual PoC — prefer that.

EXAM-BANNED — never during the exam:

  • SQLMap, SQLNinja, db_autopwn, browser_autopwn
  • Nessus, OpenVAS, Nexpose, Canvas, Core Impact, SAINT
  • Responder poisoning and all spoofing (Responder analyse-only -A is fine)
  • Commercial tools: Burp Pro, MSF Pro
  • Manual EXAM-OK alternatives for SQLMap: extractvalue() / updatexml() / sqli-labs payloads by hand

Checklist (Paste on Second Screen During the Exam)

Reconnaissance:

  • [ ] sudo nmap -Pn -sC -sV -p- -v <IP> -oN scan.txt
  • [ ] Note non-standard ports
  • [ ] Fingerprint every web port: whatweb, view source, favicon MD5
  • [ ] curl -sI every web port for headers (X-Version, X-Powered-By)
  • [ ] smbclient -N -L //<IP>, enum4linux-ng -A <IP>, anon FTP, redis-cli -h <IP>, showmount -e <IP>

Foothold:

  • [ ] Version + CVE search on every visible app
  • [ ] Try default creds before exploits
  • [ ] .git/, .env, wp-config.php, web.config exposure checks
  • [ ] For LFI: --path-as-is, data://, php://filter, /proc/self/cwd/*
  • [ ] Egress port test — for p in 80 443 4444 21 53 3000 8000; do timeout 3 bash -c "echo > /dev/tcp/<LHOST>/$p" 2>/dev/null && echo "$p OPEN"; done

Post-foothold — 30 seconds:

  • [ ] id (groups first — disk/docker/lxd/adm)
  • [ ] sudo -l
  • [ ] find / -perm -4000 -type f 2>/dev/null (BEFORE pty upgrade)
  • [ ] getcap -r / 2>/dev/null
  • [ ] cat /etc/crontab + ls /etc/cron.d/
  • [ ] ls -la /var/mail/ and read whatever you can

Post-foothold — enum sweep:

  • [ ] linpeas.sh or LinEnum.sh
  • [ ] pspy64 for >=60s
  • [ ] Every service config: .env, wp-config.php, .htusers.php, embedded DBs
  • [ ] find / -writable -type f 2>/dev/null | grep -E "\.(sh|py|conf|service)$"

Cred pivot:

  • [ ] Every found password -> su and ssh for every user in /etc/passwd
  • [ ] Crack every hash you find (bcrypt 3200 / phpass 400 / MD5 0 / PKCS5S2 12001)
  • [ ] Password reuse across FTP, SSH, WP admin, MySQL, SMB, RDP

Root:

  • [ ] Hit GTFOBins for every sudo/SUID/capability
  • [ ] Kernel exploit only when everything else fails
