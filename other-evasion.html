Endpoint Detection and Response (EDR) Bypass

Static Detection

Mechanism: Static detection analyzes files and applications without executing them, based on predefined signatures or known malicious patterns.

Bypass Techniques:

  • Obfuscate strings
  • Dynamically resolving strings
  • Dynamically resolving imports, reducing the Import Address Table (IAT)
  • Custom GetProcAddress and GetModuleHandle
  • API Hashing

User Behavioral Analysis

Mechanism: Monitors and analyzes user activities and patterns to detect anomalies.

Bypass: Learning about OPSEC methods.

Usermode Windows Function Monitoring

Mechanism: Tracks and analyzes the execution of Windows API calls within user space processes.

Bypass:

  • Unhooking
  • Indirect syscalls

Call Stack Analysis

Mechanism: Checking the origin of function calls via the Call Stack chain.

Bypass: (See references for latest techniques)

Process Analysis

Mechanism: Inspecting memory regions, identifying remote process access, and assessing child processes.

Bypass:

  • Avoid RWX memory region (use RW->RX instead)
  • Break parent-child link (e.g., word.exe spawning cmd.exe)

Kernel Callbacks

Mechanism: Functions registered by kernel drivers triggered in response to specific kernel events.

Bypass: (See kernel evasion techniques)

Command History

Prevent writing to history:

unset HISTFILE
export HISTSIZE=0

Exclude commands matching patterns (by default ignores leading whitespace):

 my-sneaky-command

Remove individual entries:

## Removes the most recently logged command (delete two entries to avoid logging the delete command itself)
history -d -2 && history -d -1

Clear all history:

history -c && history -w

Permanently disable bash history:

ln /dev/null ~/.bash_history -sf
echo "" > ~/.bash_history

Hiding Text with ANSI Escape Sequences

Hide text under certain circumstances using ANSI escape sequences:

echo "sneaky-payload-command" > script.sh
echo "# $(clear)" >> script.sh
echo "# Do not remove. Generated from /etc/issue.conf by configure." >> script.sh

## When printed, terminal clears and only the last line is visible
cat script.sh

Timestomping

Alter file timestamps to conceal modification:

## Change access and modification times using YYYYMMDDhhmm format
touch -a -m -t 202210312359 "example"

## Change using Unix epoch timestamp
touch -a -m -d @1667275140 "example"

## Copy timestamp from another file
touch -a -m -r "other_file" "example"

## Modify file while preserving timestamp
MODIFIED_TS=$(stat --format="%Y" "example")
echo "backdoor" >> "example"
touch -a -m -d @$MODIFIED_TS "example"

Note: touch can only modify access and modification times, not change or birth timestamps.

Workaround for root (modify system clock, create file, revert clock):

ORIG_TIME=$(date)
date -s "2022-10-31 23:59:59"
touch -a -m "example"
date -s "${ORIG_TIME}"

Remember: creating a file also updates the parent directory's modification timestamp!

Hiding PID Listings from Non-Root Users

Limit access to process information by modifying /proc mount options:

sudo mount -o remount,rw,nosuid,nodev,noexec,relatime,hidepid=2 /proc
  • hidepid=2: Hides all processes that don't belong to the user
  • hidepid=1: Hides only process details but still shows PIDs

AV Detection Methods — Background

AV software typically layers three detection methods:

  1. Signature-based — a unique byte sequence identifying known malware. Bypass by modifying the payload's byte sequence (encoding/packing) so it no longer matches.
  2. Heuristic-based — rule/decision-based detection looking for suspicious patterns in code structure or API call sequences.
  3. Behavior-based — monitors runtime behavior rather than static bytes (used against newer malware strains). The hardest to evade — it watches what the program does, not what it looks like.

On-Disk Evasion Techniques

  • Obfuscation — reorganizes code to make it harder to analyze/reverse-engineer without changing its function.
  • Encoding — reversible transformation into a new format (e.g. msfvenom -e x86/shikata_ga_nai); encoded → decoded back to original at runtime.
  • Packing — repackages the executable with a new binary structure/smaller size, giving it a new signature.
  • Crypters — encrypt the payload/code; decrypt in memory at runtime. The decryption key/function usually lives in a small unencrypted "stub" that does the unwrapping.

Named packers (compress EXE + embed unpack-at-runtime stub, changing bytes-on-disk): UPX, MPRESS, MEW, Morphine, Themida, Enigma, Alternate EXE Packer, ExeStealth.

Tools:

  • Shellter — inject payloads into legitimate Windows PEs
  • Invoke-Obfuscation — PowerShell v2.0+ compatible command/script obfuscator

In-Memory Evasion (Fileless)

Focuses on manipulating memory directly rather than writing files to disk — injects the payload into a running process by leveraging Windows APIs, then executes it in memory on a separate thread. Never touches disk, so static/signature scanners never see it; primarily defeated by behavior-based/EDR detection instead.

Why modern AV/EDR still catches packed/encoded payloads:

  • Encoders ≠ invisibility — shikata_ga_nai and friends only strip bad chars / change on-disk bytes; behavior + ML + memory telemetry still flag the payload at runtime.
  • Encryption ≠ stealth — TLS/AES hides content, not metadata (destinations, timing, SNI, JA3/JA4 fingerprints, beacon cadence).
  • Packed binaries leave loud signals — abnormal section names (UPX0/UPX1), very high per-section entropy, tiny import tables, and runtime VirtualAlloc→write→CreateThread with RWX memory transitions.
  • "Slower" isn't always safer — low-and-slow scans/beacons can trip anomaly detectors that model normal behavior.

Practical exam-day takeaway: don't rely on -e / -i encoding to beat modern Defender. Pair a template-injection (msfvenom -x -k) or Shellter with a genuinely different delivery (fileless PowerShell + AMSI bypass), and prefer a stageless payload over a staged one behind egress filtering. Encoding buys signature evasion only.

Exploit-Coding / Shellcode Notes

IDS/IPS signature on repeated buffer patterns and huge 0x90 NOP sleds — vary filler bytes / use mixed sleds to reduce signature hits (still behaviorally detectable).

Make targets explicit in MSF modules so return address + offset are auditable:

'Targets' => [ [ 'Windows 2000 SP4 English', { 'Ret' => 0x77e14c29, 'Offset' => 5093 } ] ],

Always validate a crafted exploit in a sandbox VM first — you often get one shot against a real target.
