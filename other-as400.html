AS/400 (IBM i)

Attacking IBM i (AS/400) midrange systems — lab setup with DVCA, the service/port map (FTP, 5250/3270, As-svrmap, As-database, DDM), terminal clients (tn5250, x3270, wc3270_hacked), default profile list, default-password hunting with ANZDFTPWD, user enumeration via telnet / POP3 / FTP error codes, user classes and special authorities (*ALLOBJ, *SECADM, *SECOFR), privesc via SBMJOB / unqualified library calls, and QSYRUPWD password cracking with John and Hashcat.

AS/400 (IBM i) is a midrange computer system developed by IBM, originally released in 1988. Now known as IBM i running on Power Systems, it is widely used for business applications due to its stability, security, and integrated database (DB2 for i).

User Classes and Authorities

User Class determines a predefined set of authorities and privileges:

User Class Special Authority
*SECOFR (Security Officer) All special authorities - full system control
*SECADM (Security Administrator) *SECADM - user management only
*SYSOPR (System Operator) *SAVSYS, *JOBCTL
*ALLOBJ (All Object Authority) Access all objects (may lack security control)
*PGMR Limited access to system administration
*USER Standard user with minimal privileges

Create high-privilege user:

CRTUSRPRF USRPRF(MYUSER) USRCLS(*SECOFR) SPCAUT(*USRCLS)

Special Authority Types

  • *ALLOBJ: Full access to any resource on the system
  • *SECADM: Create, change, delete user profiles
  • *JOBCTL: Change job priority, end jobs, delete output
  • *SPLCTL: All spool control functions
  • *SAVSYS: Save, restore, free storage for all objects
  • *SERVICE: System service tools, program debugging
  • *AUDIT: View and change auditing characteristics
  • *IOSYSCFG: Change system configuration

Print users with special authorities:

PRTUSRPRF TYPE(*ALL) SELECT(*SPCAUT) SPCAUT(*ALL)

Users assigned *SECOFR security class are automatically granted *ALLOBJ authority.

Submit job as target user:

SBMJOB CMD(DSPJOB) JOB(TESTJOB) USER(<USERNAME>)

Check job log:

WRKJOB TESTJOB

Unqualified Library Calls

Vulnerable code uses library lists instead of qualified names:

CALL OBJBAR             # VULNERABLE

Password Cracking

Requirements: *ALLOBJ and *SECADM privileges

Extract hashes with QSYRUPWD. Format UPWD0100 contains:

  • DES 56-bit encrypted password (offset 0, length 16)
  • LM hash (offset 32, length 32)
  • HMAC-SHA1 encrypted password token (offset 68, length 40)

Crack with John:

john --format=LM {filename}
john --format=as400-des {filename}
john --format=as400-ssha1 {filename}

Crack with Hashcat:

hashcat -m 3000 -a 3 --increment --username -1 ?u?d?s .\hashes.txt ?1?1?1?1?1?1?1
