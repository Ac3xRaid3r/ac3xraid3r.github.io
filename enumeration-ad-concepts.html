AD Structure & Terminology

Hierarchy (top -> bottom):

Forest (security boundary)
  - Tree (shared namespace)
       - Domain (admin boundary)
            - OU (container)
                 - Objects (users / computers / groups)
Term Definition
Forest Top container + security boundary; one or more domains sharing a schema
Domain Logical group of objects (users, computers, groups, OUs); own DB + policies
Tree Domains with a contiguous namespace (e.g. corp.inlanefreight.local)
OU Container for organizing objects + delegating admin (password resets, GPO links)
Schema Blueprint defining all object classes + attributes (user class -> instance RDS01)
Object Any AD resource; Leaf (user/computer, no children) vs Container (OU/group)
Security Principal Anything the OS can authenticate — has SID + GUID (users, computers, groups). Non-principals (contacts, printers, OUs, shares) have GUID only
GUID (ObjectGUID) 128-bit, unique enterprise-wide, never changes even after deletion
SID (objectSID) Security identifier; issued by DC; used only once (deleted account's SID never reused)
DN Full path — cn=bjones,ou=IT,ou=Employees,dc=inlanefreight,dc=local (unique in directory)
RDN Single DN component (cn=bjones) — unique within its parent OU only
sAMAccountName Legacy logon name, <=20 chars (bjones)
UPN Modern logon (bjones@inlanefreight.local)
SPN Service Principal Name — uniquely IDs a service instance; Kerberoasting target
FSP Foreign Security Principal — placeholder holding a trusted external forest object's SID

Naming/critical components (attacker-relevant):

Component Meaning / attack relevance
NTDS.dit AD database at C:\Windows\NTDS\ — holds all domain password hashes (cleartext if "reversible encryption" is enabled). The ultimate prize
SYSVOL \\<DOMAIN>\SYSVOL\ share — GPOs, logon/startup scripts. Readable by all domain users -> hunt for creds in scripts / cpassword in Groups.xml
AdminSDHolder Template ACL for protected groups; SDProp re-applies it hourly on the PDC Emulator (reverts malicious ACL persistence)
adminCount=1 Marks an account currently/formerly in a protected group — flags privileged targets
sIDHistory Previous SIDs (migrations); abusable for privilege escalation if SID filtering is off
Tombstone Deleted-object container; isDeleted=TRUE; 60–180-day lifetime
dsHeuristics Forest-wide config string; can exclude groups from AdminSDHolder protection

FSMO roles (Flexible Single Master Operation) — one holder per role:

Role Scope Function
Schema Master Forest Schema modifications
Domain Naming Master Forest Prevents duplicate domain names
RID Master Domain Allocates RID pools -> Domain SID + RID = unique object SID
PDC Emulator Domain Time sync, password changes, GPO, runs SDProp — highest-value FSMO target
Infrastructure Master Domain Cross-domain name/SID/GUID resolution

Trusts

Trust Type Direction Transitive Use
Parent-child Two-way Yes Same-forest hierarchy (auto-created)
Cross-link Two-way Yes Shortcut between two child domains
External One/two-way No (SID filtering) Domains in separate forests
Tree-root Two-way Yes New tree in a forest (auto)
Forest One/two-way Yes Between two forest roots

Critical gotcha — trust direction is OPPOSITE to access direction:

  • "A trusts B" => users in B access resources in A, not the reverse
  • Transitive: A->B->C means A trusts C
  • Non-transitive stops at the immediate trust
  • Child domains in one forest do NOT automatically trust child domains in another forest, even if the parents have a forest trust
  • M&A bidirectional trusts are a classic cross-domain attack path (Kerberoast / SID-history across the trust)

Core Protocols & Ports

Protocol Port Notes
Kerberos 88 TCP/UDP Open 88 => Domain Controller
DNS 53 UDP/TCP Locates DCs via SRV records
LDAP 389 TCP Cleartext by default
LDAPS 636 TCP SSL/TLS
Global Catalog 3268 / 3269 (SSL) Forest-wide LDAP
SMB 445 TCP Shares, SAM/LSA RPC over named pipes
Netlogon 445 (over SMB) Secure Channel, MS-NRPC

Find DCs / AD infrastructure:

# SRV record lookup — most reliable DC discovery method
nslookup -type=SRV _ldap._tcp.dc._msdcs.<DOMAIN>
nslookup -type=SRV _kerberos._tcp.<DOMAIN>

nslookup <DOMAIN>                # forward
nslookup <IP>                    # reverse -> DC hostname

# AD service fingerprint
nmap -p 88,135,139,389,445,464,636,3268,3269 <IP>

Kerberos flow (5 messages):

  1. AS-REQ — client sends timestamp encrypted with user's key
  2. AS-REP — KDC returns TGT (encrypted with krbtgt key)
  3. TGS-REQ — client presents TGT, requests service ticket
  4. TGS-REP — KDC returns service ticket (encrypted with service account's hash => Kerberoastable)
  5. AP-REQ — client presents TGS to the target service

The KDC runs on the DC; passwords never traverse the network in Kerberos.

MSRPC interfaces of attacker interest:

Interface Purpose Attack
lsarpc LSA security policy Policy enumeration (lsa_secretsdump)
netlogon Domain auth Zerologon (CVE-2020-1472)
samr Account DB (create/read users/groups) BloodHound recon, user enum (default: all authed users)
drsuapi DC replication DCSync -> extract NTDS.dit hashes

Windows/AD Hash Types (crack & PtH reference)

Hash Example / format Pass-the-Hash? Hashcat mode Notes
LM 299bd128c1101fd6 Yes (with NT) 3000 Uppercased, 7-char chunks, no salt; disabled since Vista
NT (NTLM) e46b9e548fa0d122de7f59fb6d48eaa2 Yes 1000 MD4(UTF-16LE(pw)), no salt
NTLMv1 (Net-NTLMv1) u4-netntlm::kNS:338d08...:...:cb8086... No 5500 Challenge-response; captured via Responder/relay
NTLMv2 (Net-NTLMv2) admin::N46iSNekpT:08ca45...:88dcbe...:... No 5600 Default since Win2000; relay-able
DCC2 / MSCache2 $DCC2$10240#bjones#e4e938... No 2100 Cached logons (last 10) in HKLM\SECURITY\Cache; cracking is very slow — only try weak passwords

Full NTLM hash line format: username:RID:LMhash:NThash::: (RID 500 = Administrator). Only NT and LM support Pass-the-Hash; all Net-NTLM/DCC forms are challenge-response and cannot.

Pass-the-Hash example:

netexec smb <IP> -u rachel -H e46b9e548fa0d122de7f59fb6d48eaa2
# -> [+] <DOMAIN>\rachel:<hash> (Pwn3d!)

Cracking priority (fastest -> slowest): LM -> NT -> NTLMv1 -> NTLMv2 -> DCC2. Skip DCC2 unless the password is known-weak.

Accounts & Well-Known SIDs

Account SID Note
Administrator S-1-5-<domain>-500 Cannot be deleted/locked; can be disabled/renamed
Guest S-1-5-<domain>-501 Disabled by default
SYSTEM S-1-5-18 Highest local privilege; no profile. SYSTEM on a domain-joined host ~= a domain user for enumeration
Local Service S-1-5-19 Minimal privs, anonymous to network
Network Service S-1-5-20 Presents machine creds to remote services
Everyone S-1-1-0 —
Administrators (builtin) S-1-5-32-544 Local admin
krbtgt — KDC service account; owning its hash = Golden Ticket

Quick account & privilege check on a compromised host:

Get-ADUser -Identity <USER> -Properties *      # DN, SID, ObjectGUID, UPN, SamAccountName...
whoami /priv                                    # current privileges
whoami /groups                                  # group memberships
whoami /all                                     # everything

Local vs domain accounts:

  • Local accounts (SAM DB, C:\Windows\System32\config\SAM) only log into their own host
  • Domain accounts (AD) log into any domain-joined host
  • KRBTGT and machine accounts are prime targets — KRBTGT hash forges any TGT (Golden Ticket); machine account hashes enable Silver Tickets and DCSync via delegation

Group Types & Scopes

  • Security groups assign permissions/rights
  • Distribution groups are email-only (cannot grant access)
Scope Contains members from Grants access in Stored
Domain Local Any domain Same domain only Local domain
Global Same domain only Any domain Local domain
Universal Any domain Any domain in forest Global Catalog (forest-wide replication)

Key groups: Domain Admins = Global | Enterprise Admins / Schema Admins = Universal (root domain only) | Administrators = Domain Local.

Universal -> Domain Local conversion is always allowed (useful for cross-domain access chains).

Enumeration commands:

Get-ADGroup -Filter * | select samaccountname,groupscope
Get-ADGroupMember -Identity "Domain Admins" -Recursive
Get-ADPrincipalGroupMembership -Identity <USER>

Nested group membership creates hidden privilege inheritance — a user in Help Desk -> Help Desk L1 (which has GenericWrite on Tier 1 Admins) can add themselves to Tier 1 Admins. This is exactly what BloodHound surfaces. Exchange installs several highly-privileged groups worth checking (Organization Management, Exchange Windows Permissions).

Dangerous Groups & Privileges (privesc reference)

Built-in groups equivalent to (or a path to) Domain Admin:

Group Why it's dangerous
Backup Operators SeBackup/SeRestore + logon to DC => copy SAM/NTDS.dit
Server Operators Modify services on DCs => SYSTEM
Account Operators Create/modify users+groups, logon to DC => backdoor accounts
Print Operators Logon to DC + load driver => code exec
Hyper-V Administrators If DCs are virtual => DA-equivalent (snapshot the DC VM, extract NTDS offline)
DnsAdmins DLL injection into DNS service => SYSTEM
Group Policy Creator Owners Create/edit GPOs => domain-wide push
Schema Admins Modify schema => backdoor any AD object class

Dangerous whoami /priv privileges -> attack tools:

Privilege Attack Tools
SeBackupPrivilege Copy SAM/SYSTEM/NTDS.dit robocopy, wbadmin, diskshadow
SeImpersonatePrivilege Token impersonation JuicyPotato, PrintSpoofer, RogueWinRM, GodPotato
SeDebugPrivilege Dump LSASS Mimikatz, procdump
SeLoadDriverPrivilege Load malicious driver Capcom.sys
SeTakeOwnershipPrivilege Own restricted objects —

Critical gotcha — UAC hides privileges in non-elevated sessions. Even a Domain Admin's whoami /priv looks like a standard user until you run an elevated console. Always re-check whoami /priv from an elevated prompt before concluding a privilege is absent.

Group Policy (GPO) Precedence

Processing order — LSDOU: Local -> Site -> Domain -> OU -> nested OU. Last processed wins, so a GPO on the deepest child OU overrides the domain GPO.

Conflict Winner
Domain GPO vs OU GPO OU GPO
Site GPO vs Domain GPO Domain GPO (site does NOT override domain)
Computer setting vs User setting Computer setting
Link Order 1 vs 3 (same OU) Link Order 1 (highest)
Enforced vs Block Inheritance Enforced
Default Domain Policy (Enforced) Overrides everything, all levels

Refresh intervals: Regular computers/users every 90 min ± 30 | DCs every 5 min | force with gpupdate /force.

Default GPO GUIDs: Default Domain Policy {31B2F340-016D-11D2-945F-00C04FB984F9} | Default DC Policy {6AC1786C-016F-11D2-945F-00C04fB984F9}. GPO files live in \\<DOMAIN>\SYSVOL\<DOMAIN>\Policies\{GUID}.

GPO enumeration:

Get-GPO -All
Get-GPOReport -Name "Default Domain Policy" -ReportType HTML -Path C:\report.html

GPO write permissions = attack vector. GenericWrite / WriteDacl / WriteOwner / GenericAll on a GPO lets you add a scheduled task, local admin, or startup script that pushes to every OU the GPO is linked to.

  • Weaponize: SharpGPOAbuse (AddLocalAdmin, AddComputerTask, AddUserScript)
  • Enumerate: PowerView (Get-DomainGPO), Group3r
  • Visualize paths: BloodHound (edges: AddMember, WriteDacl, GPLink)
