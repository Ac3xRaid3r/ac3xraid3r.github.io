External Reconnaissance (OSINT)

Whois & Domain Registration

Identify domain ownership and administrative contacts.

# Whois lookup
whois <DOMAIN>

Online Fingerprinting Portals

Zero-touch fingerprinting via public services — no packets from your IP hit the target.

  • Netcraft — https://sitereport.netcraft.com/?url=<DOMAIN>. Returns hosting history, OS, netblock, SSL history.
  • Wappalyzer lookup — https://www.wappalyzer.com/lookup/<DOMAIN>/ — CMS/framework/analytics/CDN detection without the browser extension.
  • Security Headers scanner — https://securityheaders.com/?q=<URL> — grades HSTS/CSP/X-Frame-Options/X-Content-Type-Options. Anything below B is worth citing in the report.
  • Qualys SSL Labs — https://www.ssllabs.com/ssltest/?d=<DOMAIN> — TLS grade, cipher list, cert chain issues. Grade B or worse = weak TLS.
  • BuiltWith — https://builtwith.com/<DOMAIN> — deeper tech-stack history.
  • crt.sh — https://crt.sh/?q=%25.<DOMAIN> — CT log lookup (also see the certificate section below).

Shodan

Shodan indexes banners from the whole IPv4 space. Fastest way to find exposed services owned by a target org.

# Filters (paste into shodan.io search)
hostname:<DOMAIN>                       # any host whose reverse DNS matches
org:"<ORG>"                             # WHOIS-registered organisation
net:<CIDR>                              # a specific netblock
ssl.cert.subject.CN:"*.<DOMAIN>"        # hosts serving a wildcard cert for a domain
port:22 country:US product:OpenSSH      # OpenSSH in US on port 22
http.title:"admin login"                # admin panels
product:Confluence version:7.13         # specific vuln targeting (CVE-2022-26134 era)
"Server: Apache/2.4.49"                 # exact banner (path-traversal era)
vuln:CVE-2021-44228                     # log4shell candidates

CLI (needs API key):

shodan init <API_KEY>
shodan search --limit 25 --fields ip_str,port,org 'hostname:<DOMAIN>'
shodan host <IP>                                        # single-host lookup
shodan count 'product:MongoDB port:27017'               # cheap volume check

Hosts File Setup

The hosts file maps hostnames to IP addresses, bypassing DNS. Essential for testing internal/lab domains.

File Locations: Windows: C:\Windows\System32\drivers\etc\hosts | Linux/MacOS: /etc/hosts

# Add target domains to /etc/hosts for local resolution
echo "<TARGET_IP>  <DOMAIN> <SUBDOMAIN>.<DOMAIN>" | sudo tee -a /etc/hosts

# Block a domain (redirect to nowhere)
echo "0.0.0.0  unwanted-site.com" | sudo tee -a /etc/hosts

Changes take effect immediately without a system restart. Edit with admin/root privileges.

Web Fuzzing with ffuf

Fast web fuzzer for directory, subdomain, parameter, and value discovery.

Directory Fuzzing

# Basic directory enumeration
ffuf -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-small.txt -u http://<IP>/FUZZ

# With extensions
ffuf -w <wordlist> -u http://<IP>/FUZZ -e .php,.html,.txt -o results.txt

# With recursion
ffuf -w <wordlist> -u http://<IP>/FUZZ -recursion -recursion-depth 2

# Case insensitive
ffuf -w <wordlist> -u http://<IP>/FUZZ -ic

# Follow redirects
ffuf -w <wordlist> -u http://<IP>/FUZZ -L

Subdomain Fuzzing

# Subdomain brute-force
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -u http://FUZZ.<DOMAIN> -fc 404

# With filtering by size
ffuf -w <wordlist> -u http://FUZZ.<DOMAIN> -fs <size>

# Virtual host (vhost) fuzzing
ffuf -w <wordlist> -u http://<IP> -H "Host: FUZZ.<DOMAIN>" -fs <filter_size>

Parameter Fuzzing

# GET parameter discovery
ffuf -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt:FUZZ -u http://<IP>/admin.php?FUZZ=key -fs SIZE

# POST parameter discovery
ffuf -w <wordlist> -u http://<IP>/admin.php -X POST -d 'FUZZ=key' -H 'Content-Type: application/x-www-form-urlencoded' -fs SIZE

# Value fuzzing (ID enumeration)
for i in $(seq 1 1000); do echo $i >> ids.txt; done
ffuf -w ids.txt:FUZZ -u http://<IP>/admin.php -X POST -d 'id=FUZZ' -H 'Content-Type: application/x-www-form-urlencoded' -fs SIZE

ffuf Filtering & Matching

-mc 200,301       # Match these codes
-mc 200-299       # Match range
-fc 404           # Filter these codes
-fc 400-500       # Filter range
-fs <size>        # Filter by response size (bytes)
-fw <words>       # Filter by word count
-fl <lines>       # Filter by line count
-mr "pattern"     # Match by regex
-fr "pattern"     # Filter by regex
-mt <ms>          # Match response time

Advanced ffuf Features

# Multiple wordlists
ffuf -w list1:W1 -w list2:W2 -u http://target/W1/W2

# Custom rate limiting
ffuf -w <wordlist> -u http://<IP>/FUZZ -rate 500

# Threads
ffuf -w <wordlist> -u http://<IP>/FUZZ -t 100

# Output to file
ffuf -w <wordlist> -u http://<IP>/FUZZ -o results.json -of json

Web Fuzzing with Gobuster

# Directory brute-force
gobuster dir -u http://<IP> -w <wordlist> -x php,html,txt

# Subdomain enumeration
gobuster dns -d <DOMAIN> -w <wordlist> -r <DNS_IP>

# Virtual host fuzzing
gobuster vhost -u http://<IP> -w <wordlist>

# Flags: -t threads, -o output, -q quiet, --statuscode 200,204, --timeout 10s

API version pattern mode (-p) — fuzz /<word>/v1, /<word>/v2 instead of the plain wordlist. Great for REST APIs where every collection lives behind /v1 or /v2.

Create pattern:

{GOBUSTER}/v1
{GOBUSTER}/v2

Run:

gobuster dir -u http://<IP>:5002 -w /usr/share/wordlists/dirb/big.txt -p pattern
# each wordlist entry is substituted into {GOBUSTER}; both v1 and v2 tried per word
# hits like /books/v1, /users/v1 pop out

Web Fuzzing with Feroxbuster

# Basic directory enumeration
feroxbuster -u http://<TARGET> -w <wordlist>

# Recursive scanning
feroxbuster -u http://<TARGET> -w <wordlist> --depth 3

# Additional extensions
feroxbuster -u http://<TARGET> -x php,html,js,json

# Filter responses

Virtual Host (vhost) Enumeration

Discover applications hosted on same IP with different Host headers.

VHost Types

Type How It Works When Used
Name-Based (most common) Routes by Host header; many sites share one IP. TLS via SNI Normal web apps, modern clients, limited IPs
IP-Based One site per IP; server selects by destination IP Strict isolation/compliance, legacy TLS
Port-Based Same IP, different ports per site (:80, :8080) Internal tools/labs, quick demos

VHost vs Subdomain: A subdomain is a DNS label/name. A VHost is a web-server routing config that may or may not correspond to a DNS subdomain. VHost fuzzing finds hosts that have no public DNS records.

VHost Fuzzing Workflow

  1. Run initial scan without filters — note the default response size
  2. Add -fs <default_size> to filter out the default page
  3. Results with different sizes = real virtual hosts
  4. Add discovered vhosts to /etc/hosts
# ffuf vhost fuzzing
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ -u http://<IP>:PORT/ -H 'Host: FUZZ.<DOMAIN>' -fs <DEFAULT_SIZE>

# Gobuster vhost mode (--append-domain appends base domain to each word)
gobuster vhost -u http://<TARGET_IP> -w <wordlist> --append-domain
gobuster vhost -u http://<TARGET_IP> -w <wordlist> --append-domain -t 50 -k

# Add discovered vhosts to /etc/hosts
echo "<TARGET_IP> app.<DOMAIN> dev.<DOMAIN>" | sudo tee -a /etc/hosts

Subdomain Brute-Force Workflow

  1. Pick wordlist — General (subdomains-top1million-5000.txt), targeted (industry/stack), or custom (intel-driven)
  2. Generate candidates — Append words to root domain (tools: dnsgen, simple scripts)
  3. Resolve DNS — Query A/AAAA for each candidate (tools: puredns resolve, dnsx, massdns)
  4. Filter & validate — De-wildcard; probe HTTP/HTTPS for live hosts (httpx/curl); dedupe & save

Passive + Active

# Subfinder + AMASS, combine and dedupe
subfinder -d <DOMAIN> -o subfinder_results.txt
amass enum -d <DOMAIN> -o amass_results.txt
cat subfinder_results.txt amass_results.txt | sort -u > combined_subdomains.txt

# DNS resolution, filter live hosts
subfinder -silent -d <DOMAIN> | dnsx -silent -a -resp > resolved.txt
cat resolved.txt | grep -v NXDOMAIN | cut -d' ' -f1 | sort -u > live_subdomains.txt

Certificate Transparency (CT) Logs

Public, append-only logs of all CA-issued SSL/TLS certificates. Enumerates real, issued hostnames without guessing and surfaces legacy/expired certs pointing to stale services.

# CLI lookup — find all subdomains via CT logs
curl -s "https://crt.sh/?q=%25.<DOMAIN>&output=json" | jq -r '.[].name_value' | sort -u

# Filter for specific subdomain pattern (e.g., "dev")
curl -s "https://crt.sh/?q=<DOMAIN>&output=json" | jq -r '.[] | select(.name_value | contains("dev")) | .name_value' | sort -u

Crawling Tips

  • Seed from robots.txt, sitemaps, CT/DNS findings
  • Handle auth (cookies/headers); respect sessions and CSRF tokens
  • De-duplicate by canonical URL; capture parameters; store response hashes
  • Rate-limit and randomize delays; obey ToS; exclude logout/admin by default

Directives Reference

Quick Extraction

curl -s https://<TARGET>/robots.txt | grep -Ei '^(Disallow|Allow|Sitemap|Crawl-delay):'

Recon value: Disallowed paths often reveal admin areas, backup directories, staging environments, and API endpoints. Always treat disallowed paths as leads for further investigation (within scope). Watch for honeypots — some sites include trap paths like /honeypot/ to detect unauthorized crawlers.

Virtual Host Enumeration — From SSL Certificates

SSL certificates on internal web services often reveal internal domain names and virtual hosts. Extract Subject Alternative Names (SANs) from HTTPS services.

# Extract all domain names from SSL certificate
openssl s_client -connect <IP>:443 2>/dev/null | openssl x509 -noout -text | grep -i "dns:"

# Save certificate and extract vhosts
openssl s_client -connect <IP>:443 -showcerts 2>/dev/null | openssl x509 -noout -text | grep -oP 'DNS:\K[^,]+' | sort -u

# Add discovered vhosts to /etc/hosts
echo "<IP> discovered.vhost.local" >> /etc/hosts

Active Virtual Host Fuzzing

ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
  -u http://<IP>:PORT/ \
  -H 'Host: FUZZ.<DOMAIN>' \
  -fs 900 -fc 400,404

gobuster vhost -u http://<IP> -w <wordlist>
nmap --script ssl-cert <IP> -p 443

Key insight: Web applications often hosted on same IP with different Host headers. Certificate SANs reveal internal vhosts before fuzzing. Always check SSL certs first.

HTTPS Virtual Host Fuzzing

When all HTTP vhost responses return the same size (default page), switch to HTTPS and filter by response size:

# Baseline: check default HTTPS response size first

DNS Zone Transfers (AXFR)

A misconfigured DNS server may allow full zone transfers, leaking all subdomains, IPs, and name server records.

# Attempt zone transfer against a name server
dig axfr @<NS_SERVER> <DOMAIN>

# Find authoritative NS first, then try AXFR on each
dig NS <DOMAIN> +short
dig axfr @<NS1> <DOMAIN>

Most modern DNS servers restrict zone transfers to trusted secondaries. Always try — a successful AXFR is a goldmine for subdomain and infrastructure mapping.

dnsenum — Comprehensive DNS Enumeration

# Full enumeration with brute-force and recursive search
dnsenum --enum <DOMAIN> -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt -r

# Basic enumeration
dnsenum <DOMAIN>

What dnsenum does in one run: pulls A/AAAA/NS/MX/TXT records, attempts AXFR on found name servers, brute-forces subdomains with a wordlist, scrapes Google for additional subdomains, performs reverse DNS on discovered IPs, and grabs WHOIS metadata.

DNS Recon Checklist

  • Confirm in-scope domains; use clean resolver; log queries
  • Grab A/AAAA, CNAME, NS, MX, TXT (SPF/DMARC/DKIM), SRV, CAA records
  • Passive subdomain discovery (CT logs, search engines) -> Active brute-force (subfinder -> puredns/dnsx) -> Permutations (dnsgen)
  • Identify authoritative NS; attempt AXFR; note DNSSEC
  • Flag CNAMEs pointing to cloud services; test for dangling/takeover
  • Parse SPF includes; find DKIM selectors; DMARC gaps indicate spoof risk
  • Query SRV records (_ldap._tcp, _sip._tcp, _kerberos._tcp) for hidden services
  • Resolve all findings -> IP/ASN/CDN/WAF mapping; spot legacy hosts
  • Diff new/removed records over time; alert on vpn/dev/stg/backup/old subdomains

WAF / "Localhost-Only" API Bypass via Headers

When to use: Endpoint returns 403 WAF: Access Denied for this Host or similar. Iterate client-controlled headers before assuming the endpoint is truly restricted. Half the "protected" internal APIs on OSCP-style boxes are gated by one client-controlled header.

Header rotation cheat sheet:

X-Forwarded-For: 127.0.0.1        <- wins most often
X-Real-IP: 127.0.0.1
X-Client-IP: 127.0.0.1
X-Originating-IP: 127.0.0.1
Forwarded: for=127.0.0.1
X-Forwarded-Host: localhost
Host: localhost
Host: 127.0.0.1

Automated with curl:

for h in "X-Forwarded-For: 127.0.0.1" "X-Real-IP: 127.0.0.1" "X-Client-IP: 127.0.0.1" "Forwarded: for=127.0.0.1" "Host: localhost"; do
  echo "=== $h ==="
  curl -s -H "$h" http://<IP>/api/internal | head -c 200
  echo
done

WordPress Vhost Catch-All Filter (nginx WordPress)

When to use: nginx-hosted WordPress returns 301 -> http://<vhost>/... on any unknown path. Standard gobuster returns nothing but 301s of a fixed size. This is a WordPress catch-all — filter it out.

# 1. Add vhost to /etc/hosts first
echo "<IP> <vhost>" | sudo tee -a /etc/hosts

# 2. Inspect one 200 or 301 response to get the exact catch-all body size
curl -s http://<vhost>/definitely-does-not-exist | wc -c
# -> e.g. 51576 bytes

# 3. Filter that size with gobuster
gobuster dir -u http://<vhost>/ \
  -w /usr/share/wordlists/seclists/Discovery/Web-Content/common.txt \
  -x php,txt,html -b 301,404 --exclude-length 51576 -t 30
#   --exclude-length SIZE    hide responses of this exact size (WP catch-all)

Recognizing the trap: /.git/logs/ and /cgi-bin/ returning 200 with identical sizes = WP catch-all, not real files. If every "found" path returns the same size, you're being trolled by WordPress rewrite rules.
